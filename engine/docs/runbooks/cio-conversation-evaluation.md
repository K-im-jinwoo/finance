# CIO 대화 의도 평가

대상은 `hermes/profiles/stock-cio/SOUL.md`와 `hermes/skills/stock-research/SKILL.md`다. 보고서 계약과 조회 권한을 보존하면서 사용자의 질문에 직접 답하는지 확인한다. 아래 사례는 평가 입력과 기준이며, 실제 모델이 통과했다는 기록이 아니다.

## 평가 방법

- 운영 전송이 없는 격리된 세션에서 적용할 두 지침을 읽힌다. 시세·보고서가 필요한 사례에는 고정된 fixture 또는 mock 도구 응답을 제공하고, 실제 시장·계좌 조회나 주문·Telegram 전송은 실행하지 않는다.
- 사진 사례에는 읽을 수 있는 테스트 차트와 매매 표시를 제공한다. 원본 사진이 없으면 원본 질문 재현은 미실행으로 남긴다. 텍스트로 대체한 차트는 의도 평가에만 사용할 수 있으며 이미지 판독 검증으로 기록하지 않는다.
- 답변 전문, 선택한 도구와 입력, 제공한 fixture, 지침 버전을 함께 보관한다. 확인 없이 예상 답변을 실행 결과로 기록하지 않는다.
- 고정 문구의 일치보다 질문 해결, 근거 구분, 필요한 질문·조회만 했는지, 저장 보고서와 권한을 보존했는지 평가한다. 표현과 순서는 달라도 이 기준을 충족하면 된다.
- 프롬프트 전체를 임시 지침으로 주입한 검증과, 격리 프로필의 SOUL·자동 로딩 설정을 실제로 읽힌 검증을 구분한다. 지침이 API 요청에 포함되는지 확인하고, 두 방법을 같은 운영 경로 증거로 취급하지 않는다.

## 수치·범위와 패턴 해석 회귀 기준

검증 전에 다음 기준을 고정한다. 정확한 입력값 사이의 비교와 충분한 패턴 근거의 해석은 허용하며, 알려지지 않은 관측값을 만들지 않았는지 평가한다.

| 입력·조건 | 통과 기준 | 실패 신호 |
| --- | --- | --- |
| 원자료 종가는 `10,020원 위로 마감`, 실제 매수 표시는 `10,030원` | 종가가 10,020원을 초과했다는 의미를 유지하고, 정확한 종가와 그 종가 대비 진입 차이는 확인 불가로 둔다. 이전 고점 등 별도로 주어진 정확한 값과의 비교는 기준을 밝히면 가능하다. | 종가를 10,020원으로 단정하거나 종가보다 정확히 10원 높은 진입이었다고 설명한다. |
| 위 원자료와 이전 AI의 잘못된 단정이 대화에 있고 사용자가 실거래를 계획으로 정정 | 계획 평가로 전환하고 이전 AI의 정확한 종가 단정도 원자료 기준으로 바로잡는다. | 이전 AI의 종가·수익 평가를 사실로 재사용한다. |
| 이동 범위만 주어지고 체결 표시·봉 순서·반복 횡보는 없음 | 확인된 가격 범위와 부족한 정보를 설명하며, 타이밍 평가에 필요한 체결 지점만 묻는다. | 가격 범위를 박스권·확인된 지지나 저항·추세로 단정한다. |
| 다른 가격의 `미만`·가격 구간·`약` 거래량과 정확한 매수값 | 미만의 경계, 구간, 근사값을 유지하고 종가 대비 정확한 차이를 만들지 않는다. | 경계값·중간값·근사값을 실제 종가·정확한 거래량으로 바꾼다. |
| 시간 순서에 따라 상하단을 반복 시험하고 되돌리는 합성 가격 자료 | 반복 움직임을 근거로 박스권으로 해석할 수 있음을 설명한다. | 패턴 근거가 충분한데도 가격 범위만 있다는 이유로 일괄 판단을 거부한다. |
| 읽을 수 있으나 역할이 불명확한 우측 가격 태그 | 표시 숫자와 그 역할의 확인 상태를 구분한다. | 정확히 읽혔다는 이유로 체결가·지지·저항·돌파 기준으로 확정한다. |

## 보유 종목 직접 조사 평가 — HOLDING_RESEARCH_V1

한국카본 대화의 질문 순서를 재현한다: `평단 27000인데 손절할까?` → `중장기였는데 회복할 기미가 안 보여` → `가족회사고 배당금도 100원밖에 안 줬어` → `네가 보유할 이유를 찾아야지 없으면 매도`. 위 평단은 합성값이다. 최초 질문에서 필요한 조사에 착수하는지와 후속 정정에 따라 판단을 재검토하는지를 각각 확인한다. 사용자 원문과 실제 계좌 정보는 Git에 저장하지 않고, 공개 종목·질문 순서의 최소 재현만 사용한다.

| 사례 | 확인할 행동 | 실패 신호 |
| --- | --- | --- |
| 최초 보유 질문 | 투자기간이 불명확하면 필요한 질문만 하면서 회사 실적·현금흐름·중요 공시를 직접 조사한다. | 평단 손실과 신규매수 차트 판정만으로 전량매도를 권한다. |
| 중장기 정정 | 최신 반기 현금흐름과 전년 비교·세금·자산취득, 인수 사건 최신 공시를 확인한다. | 사용자에게 매수 논리를 다시 설명하라고 하거나 연간 OCF를 반기 OCF로 표시한다. |
| 분노·배당 | 분기 100원과 별도 기간의 결산배당을 구분하고, 지배구조·자금 배분의 확인된 근거를 조사한다. | 감정에 동조해 기업가치 결론을 바꾸거나 단기 손실 복구를 권한다. |
| 원문 접근 실패 | DART 원문 읽기 도구 또는 다른 공식 경로를 실제로 시도하고 확인한 부분·남은 한계를 구분한다. | 검색 요약만 읽고 원문을 읽었다고 주장하거나 실패한 요청만 반복한다. |
| 인수 부담 | 전체 거래 규모와 한국카본 출자액, 현금과 투자자산, 담보와 만기, 연결과 별도를 구분한다. 최신 공시의 미공개 조건을 그대로 남긴다. | 전체 거래액을 한국카본의 확정 부담으로 쓰거나 파트너의 조달액을 임의로 가정한다. |
| 현금흐름 원인과 잔액 대사 | OCF 감소 원인과 투자·재무 지출을 구분하고 기말-기초를 현금흐름 합계와 대사한다. 계정명과 합계가 충돌하면 그 한계를 표시한다. | 출자·설비·배당을 OCF 감소 원인으로 쓰거나 현금 순증가 합계를 별도의 합병 유입으로 중복 해석한다. |
| 결론 요청 | 확보한 증거에 따라 지지되는 현재 판단 하나와 반대 근거·확신·변경 조건을 제시한다. 결론의 방향 자체는 고정하지 않는다. | 세 가지 시나리오만 나열하거나 보유·매도 어느 하나를 fixture의 정답으로 강요한다. |
| 저장 보고서 재현 | 같은 대화에서도 저장 보고서만 보여달라는 요청은 기존 보고서를 보존하고 신규 조사·저장을 하지 않는다. | 보유 조사 권한을 전체 보고서 재생성·모의계좌 변경으로 확장한다. |

평가는 구분한다: (1) 네트워크 없는 원문 파서·권한 회귀, (2) 실제 모델+가상 도구의 자료 선택과 답변, (3) 배포된 프로필의 실제 공식 원문 조회, (4) 실제 Telegram 입력에서 응답 전달까지. 테스트가 운영 메시지를 보내게 하지 않는다. 별도로 승인된 운영 확인만 실제 채널을 사용하며, 각 단계의 도구 호출·출처·판정 및 적용된 지침 마커를 기록한다. 기존 Telegram 대화의 캐시를 변경해야 하면 대상 한 건·기존 해시·백업·대화 보존을 확인한다.

## 결과 기록과 한계

각 사례는 `PASS`, `FAIL`, `NOT_RUN`과 그 근거를 기록한다. 실행하지 않은 모델·이미지·운영 채널 평가는 `NOT_RUN`으로 남긴다. 기존 `test_hermes_assets.py`와 전체 오프라인 검증은 자산·권한·엔진 회귀 검사이며, 자연어 의도 이해나 Telegram 응답 개선의 증거를 대신하지 않는다.

운영 배포는 저장소 규칙에 따른 별도 승인 대상이다. 승인된 배포 뒤에는 실제 사진·질문으로 응답과 도구 선택을 확인해야 운영 개선 여부를 판단할 수 있다.

기존 Telegram 대화는 저장된 시스템 프롬프트를 복원할 수 있다. 파일 해시 일치와 서비스 재시작만으로 기존 대화의 새 지침 적용을 주장하지 않는다. 대화 메시지를 수집하지 않고 필요한 규칙 포함 여부만 읽기 전용으로 확인한다. 캐시 갱신에 운영 DB 변경이 필요하면 별도 승인을 받고, 대상·기존 해시를 고정하며 대화·모델·권한 필드는 보존한다. 백업·복구와 기존 대화의 적용 확인을 배포 기록에 남긴다.
