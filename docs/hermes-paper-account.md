## 선택과 원장

- 명시적 번호·6자리 종목 코드·리서치 등급·행동 판정·단일 보고서 ID·완료된 CIO 최종 답변이 필요합니다. 중복 순위/종목·누락/모호한 판정·완료되지 않은 답변이면 원문 열람만 제공합니다.
- 1순위가 PRIORITY_REVIEW이고 EXCLUDED가 아닐 때 실험 신호를 생성합니다. 나머지 추천은 보고서에 표시합니다. 1순위가 보유 중이면 추가매수 없이 보유를 유지합니다. 순위 하락이 자동 청산을 발생시키지 않습니다.
- 계좌 시작 때 최신 보고서는 **지금 확보한 신호**로 채택합니다. Hermes 원래 생성 시각을 체결 대기 생성 시각으로 소급하지 않습니다. 이후 최신의 새 최종 답변만 신호로 처리합니다.
- 초기 1천만원·총자산 20%에 매수비용 포함·정수 주식·각 방향 15bps·현금 부족 보류·최대 5종목을 기존 엔진에서 재사용합니다. 경계/반올림/동일 시가 순서 등 기존 미결정 구현안의 상태를 유지합니다.
- PAUSE는 모든 대기 거래를 취소합니다. 데이터/평가는 계속하며 RESUME 이후에 **실제로 새로 생성된** Hermes 최종 답변이 있어야 거래가 생깁니다. 재개 전에 생성된 답변을 나중에 처음 읽어도 재개 신호로 쓰지 않습니다.
- 별도 `.runtime/hermes-paper.sqlite3`에 규칙 스냅샷·보고서·사건·현금을 저장합니다. 기존 `.runtime/paper.sqlite3` 실험과 원본 운영 DB/보고서/완료 성과를 변경하지 않습니다. 실제 원문 캐시는 Git 제외 영역에만 둡니다.

## 시세와 수익률

현재 연결은 운영 `market_quotes` 테이블을 SQL `mode=ro`와 `query_only=ON`으로 읽는 방식입니다. 원본 약 5분 수집, 대시보드 30초 확인, 브라우저 5초 화면 갱신입니다. 실시간 틱이라고 표시하지 않습니다. 시세 원래 시각·운영 관측 시각·로컬 확보 시각을 구분합니다. 공급자 가격을 운영 DB에 재저장하지 않습니다.

종목별 평가손익은 `현재가 × 수량 − (매수원금 + 매수비용)`, 순수익률은 `현재 평가금액 / 취득 총비용 − 1`입니다. 매도비용을 미리 이중 차감하지 않습니다. 매도 시 실제 가상 체결 비용을 원장에 반영합니다. 체결 전에는 종목 수익률이 없으며, 5분 초과/미래/0원/잘못된 통화/진입 이전 시세는 현재 손익으로 인정하지 않습니다. 마지막 시세는 지연 상태와 시각을 표시할 수 있지만 현재 수익률은 null입니다.

## 실제 시가 어댑터의 미통과 조건

토스 [공식 OpenAPI 명세](https://openapi.tossinvest.com/openapi-docs/latest/openapi.json) 1.2.19를 확인했습니다. 같은 client에서 토큰을 다시 발급하면 기존 토큰을 즉시 무효화하므로 운영 수집기와 인증을 공유해 반복 발급하지 않습니다. `--direct-market`은 이미 승인·등록된 별도 공개 데이터 인증이 필요하며, 운영 수집기와 같은 client ID이면 연결을 거부합니다. 원격 등록/설정/배포는 수행하지 않았습니다. 주문·실계좌 엔드포인트는 호출하지 않습니다.

준비된 실제 시가 경로는 공식 KR 정규장 달력과 `adjusted=false` 1분봉입니다. 공식 명세의 일반 종목 1분봉 timestamp는 **종료 시각**이므로 09:00 시가는 09:01 종료 봉의 openPrice를 사용합니다. 시장지표 분봉의 시작 시각 계약과 혼동하지 않습니다. 거래량이 양수이고 봉이 완성돼야 합니다. 실제 거래일은 달력으로 확인하며 평일 계산으로 추정하지 않습니다.

현재 로컬 구현 제안은 첫 분봉 완성 후 정규장 시작 5분 안에 관측하고, 수집기와 달력을 시가 전에 확보했을 때만 체결하는 것입니다. 이것은 확정된 사용자 운용 규칙이 아니며 실제 공급자 경로 검증과 관측 지연 선택 전에는 승인된 운용으로 표시하지 않습니다. 별도 인증이 있어도 `--direct-market`만으로는 시가 체결을 활성화하지 않습니다. 실제 검증·정책 승인 후에만 `--enable-open-fills`를 사용합니다. 서버를 장 시작 후 재시작한 경우 과거 시가를 넣지 않습니다. 현재 운영 저장소의 수정가격 분봉을 원시가격으로 간주하지 않아 가상 체결은 대기 중입니다.
