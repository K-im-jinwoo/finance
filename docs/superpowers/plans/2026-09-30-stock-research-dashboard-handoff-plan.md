# 주식 리서치 대시보드 구현 계획

작성 기준: 2026-09-30 KST

상태: 사용자 선택에 근거한 1차 실행 계획, 개발 착수 전

근거: [주식 리서치 대시보드 인수인계 보고서](../../reports/2026-09-30-stock-research-dashboard-handoff-report.md)

현재 후보 선정과 가격·재무 무효화 규칙의 성과를 검증하는 자동 모의투자 시스템을 새 프로젝트에서 구축한다. 계산과 모의계좌 원장을 먼저 검증하고, PC·모바일 대시보드와 Telegram을 동일한 저장 결과에 연결한다. 첫 작업은 최근 3년 데이터의 확보 범위 조사와 자동 무효화 규칙 명세화다.

## 확정 범위

- 자동 모의계좌만 운영한다. 우선 검토 등급인 `BUY_HOLD`도 사용자가 승인한 실험 편입 대상이다. 원본의 매수 보류 판정은 보존한다.
- 초기자금 10,000,000원, 신규 매수 시 총자산의 20%씩, 최대 5종목을 보유한다. 반복 추천으로 추가매수하거나 매일 비중을 맞추지 않는다.
- 보고서 생성 이후 최초 거래 가능한 시가에 매수한다. 무효화 확인 이후 최초 거래 가능한 시가에 전량 매도한다.
- 후보 순위에서 빠져도 무효화 전까지 보유하고 계속 점검한다. 첫 검증에는 별도 손절·익절률을 추가하지 않는다.
- 가격·재무 조건부터 자동 무효화한다. 공시 조건은 확인 필요로 표시한다. 데이터 부족을 무효화로 단정하지 않는다.
- 무효화 원인이 해소된 새 데이터와 우선 검토 재선정을 확인해야 재진입할 수 있다.
- 왕복 0.3% 비용 가정과 비용별 비교를 제공한다. 최근 3년을 목표로 하되 검증 가능한 기간과 누락 범위를 명시한다.
- PC와 모바일에서 자산·수익률·최대낙폭과 오늘의 변화를 우선 표시한다.
- 거래일 저녁 요약 1회와 매수·매도·무효화·오류 알림을 Telegram으로 전달하고 해당 상세 화면에 연결한다.
- 대시보드에서 실험 시작·일시중지와 새 설정의 별도 실험 생성을 지원한다. 이전 설정과 결과를 보존한다.

가상 거래는 전용 모의 원장에서만 실행한다. 기존 실제 보유 원장, 원본 보고서, 실제 증권사 주문 경로와 분리한다. 현재 선정 정렬과 DART 수집 대상, 기존 실시간 오버레이의 저장 보고서 분리 규칙을 유지한다.

## 단계 0 프로젝트 기반과 재사용

새 프로젝트 위치와 기술 스택은 아직 정하지 않았다. 원본 Python의 지표·선정·시점 검증을 재사용하고 새 프로젝트가 실험 원장과 대시보드를 관리하는 구성을 우선 검토한다. 재사용은 현행 계산 규칙과 공개 인터페이스를 보존할 수 있는 범위로 제한한다.

원본 HEAD에는 현재 작업 트리의 모든 수정이 포함돼 있지 않다. 커밋만 복제해 같은 구현을 확보했다고 가정하지 않는다. 필요한 `src/stock_assistant` 모듈·테스트·정규화 계약을 검토하고 가져올 방법을 결정한다. 비밀정보, 운영 DB, 보유정보, 환경 파일, 원본 로그는 자동 복사하지 않는다.

Telegram과 화면에서 자연어 답변을 다시 해석해 수익률을 계산하지 않는다. 두 채널은 같은 보고서·실험·거래의 구조화된 데이터를 사용한다. 계산은 결정적 코드로 처리하고 모델의 설명과 구분한다.

## 단계 1 과거 데이터 확보 범위 조사

최근 3년은 목표 기간이다. 정확한 시작·종료 날짜는 데이터 가용 범위와 평가 기준일을 확인한 뒤 실험 설정에 저장한다.

| 데이터 | 확인할 내용 |
| --- | --- |
| 일별 가격·거래량 | 시가·종가·거래대금, 누락·중복, 거래일 달력, 최소 지표 준비 기간 |
| 재무 | 당시 공개된 연간·TTM 영업이익·OCF 등, 금융회사·ETF의 별도 기준, 공시 시각과 정정 이력 |
| 공시·재료 | 선정에 사용한 근거의 당시 가용성, 수집 범위, 제목 분류와 상세 확인의 차이 |
| 종목 구성 | 당시 상장·상장폐지·종목 유형, 거래정지와 코드 변경 |
| 기업행위 | 분할·병합·배당의 처리 방식과 가격·보유수량의 일관성 |
| 벤치마크 | 선택한 시장과 기간에 맞는 비교 지수, 가격수익률·총수익률의 비교 기준 |

공시 자동 무효화를 후속 범위로 두더라도 선정 점수에 공시를 사용한다면 과거의 가용 시각을 지켜야 한다. 최신 재무나 최신 후보를 과거 전체에 적용하지 않는다. 현재 관측시각을 과거로 임의 변경해 시점 검증을 통과시키지 않는다.

준비 결과는 데이터셋 식별자, 실제 지원 기간, 원본·관측·공개 시각, 공급자, 누락 종목·기간, 보정 방식으로 기록한다. 공급자 정책·사용 권한과 기술적 수집 가능 범위도 확인한다. 부족하면 검증 가능한 기간을 제시하고, 누락된 구간을 검증 완료로 표시하지 않는다. 테스트용·배포 점검용 보고서는 정상 추천 표본에서 구분한다.

## 단계 2 운용 규칙 명세

### 매수와 자금 배정

보고서의 최종 선정 후보 중 `PRIORITY_REVIEW`를 편입 대상으로 삼는 것을 구현 기준안으로 한다. 상위 후보 외의 전체 우선 검토 종목으로 범위를 넓힐지는 미결정이며, 임의로 확장하지 않는다. `BUY_HOLD` 실험 편입은 원본 판정 승격을 의미하지 않는다.

신호 생성시각, 입력 데이터의 이용 가능 시각, 주문 대기시각, 실제 거래 가능 시각을 구분한다. 장 시작 전 보고서는 당일 시가, 장 마감 후 보고서는 다음 거래일 시가가 될 수 있다. 기존 `event_study()`의 날짜 다음 거래일 진입 규칙을 그대로 사용하면 오전 신호의 새 규칙과 어긋난다.

매수 때 총자산의 20%를 목표로 한다. 동일 시점의 여러 신호에 적용할 평가자산 기준과 우선순위를 고정하고 수수료를 포함해 현금이 음수가 되지 않도록 한다. 수량 단위·반올림, 목표 금액보다 현금이 부족할 때 축소매수 또는 편입 보류 중 어떤 처리를 할지는 명세에서 확정한다. 보유 한도가 찼다는 이유로 유효한 기존 종목을 교체하지 않는다.

### 무효화와 청산

각 조건은 설명문, 판정 코드, 적용 종목 유형, 입력 데이터, 확인 시각, 판정 결과를 가진다. 보고서 문구를 모델이 임의로 해석해 가상 청산을 실행하지 않는다.

| 조건 | 첫 버전의 명세 작업 |
| --- | --- |
| 가격 | 기존 종가·20일 이동평균 이탈 조건을 기준으로 `<` 또는 `<=`, 이동평균 갱신, 판정 시점과 가격 보정 방식을 명시 |
| 일반기업 재무 | 기존 영업이익·OCF 필수조건의 위반 판정을 매핑하고 공시 전 수치 사용을 금지 |
| 금융회사·ETF | 일반기업 재무 조건을 일괄 적용하지 않고 기존 별도 계약과 자동 판정 가능 범위를 확인 |
| 공시·재료 | 확인 필요와 미적용 범위를 표시하며 첫 버전의 자동 청산으로 확대하지 않음 |
| 데이터 누락·오래됨 | 확인 불가 상태와 사유를 표시하고 무효화와 구분 |

모의계좌의 모든 보유종목을 계속 평가한다. 순위 탈락이나 보고서 미포함 자체는 청산 사유가 아니다. 무효화를 확인한 뒤 최초 거래 가능한 시가에 전량 청산하고 원인·증거·판정시각·체결시각을 연결한다. 종가에서 조건을 확인했다면 그 이전의 같은 날 시가에 소급 매도할 수 없다.

### 재진입과 실행 상태

재진입은 마지막 무효화 원인의 해소 증거가 있는 새 데이터와 우선 검토 재선정을 요구한다. 같은 스냅샷으로 매도와 재매수를 반복하지 않는다. 해소 증거가 없으면 재진입하지 않고 그 이유를 표시한다.

실험 상태는 실행 대기·실행 중·일시중지·완료·실패를 구분한다. 일시중지가 신규 거래·대기 거래·데이터 수집·평가 각각에 미치는 영향, 재개 시 오래된 신호와 놓친 체결의 처리를 확정한다. 중지 기간의 과거 시가로 나중에 체결을 소급 생성하지 않는다. 실패와 사용자 일시중지를 같은 상태로 처리하지 않는다.

### 비용과 실험 종료

왕복 30bps를 기본 가정으로 표시하되 매수·매도 비용의 부과 시점, 비용 배분과 반올림을 명시한다. 기존 이벤트 연구는 총수익률에서 비용을 단순 차감하므로 새 원장의 수수료 부과 방식과 동일하다고 가정하지 않는다. 비용을 손익에서 중복 차감하지 않는다.

실험 종료 시 열린 포지션을 평가만 할지 강제 청산할지 구분한다. 기본 청산은 무효화에 따르므로 기간 종료를 실제 무효화로 기록하지 않는다. 미청산 포지션과 미도달 성과를 별도 표시한다.

## 단계 3 모의계좌 원장과 추적 구조

다음 데이터 구조는 구현 제안이며 실제 스키마 명칭은 새 프로젝트에서 정한다.

| 데이터 | 필요한 정보 |
| --- | --- |
| 실험 | 실험 ID, 규칙 버전, 설정 스냅샷, 데이터셋·기간·비용 가정, 실행 상태 |
| 추천 관측 | 원본 보고서 ID, 종목·시각, 원래 판정·등급·점수, 신규·유지·재검토 상태 |
| 보유 구간 | 종목·최초 편입 근거, 진입·청산 시각, 무효화 원인, 반복 추천 연결 |
| 가상 거래 | 매수·매도 대기와 체결 상태, 수량·가격·비용, 미체결·보류 사유 |
| 현금·평가 | 현금 원장, 평가가격의 기준시각, 보유수량·평균단가, 자산·손익 |
| 무효화 관측 | 조건 코드, 확인·불충족·확인 불가, 근거 데이터와 확인시각 |
| 알림 이벤트 | 이벤트 ID, 대상 거래·보고서·실험, 발송 상태·재시도·중복 방지 키 |

자산은 현금과 보유 평가금액의 합으로 계산한다. 하나의 추천이 여러 보고서에 반복돼도 보유 구간은 그대로 유지한다. 원장 갱신과 거래 중복 방지는 트랜잭션으로 처리하며 같은 실행을 재시도해도 수량·현금·알림이 증가하지 않아야 한다.

초기 검증은 작고 재현 가능한 데이터셋으로 한다. 실행 속도나 화면 구현보다 시간순 계산과 원장 일치 여부를 먼저 확인한다.

## 단계 4 백테스트와 조회 계약

추천 종목의 5·20·60거래일 사후 수익률, 규칙에 따른 계좌 수익률, 실제 앞으로 진행하는 자동 모의운용 결과를 구분한다. 종목별 평균 수익률을 계좌의 누적 수익률로 표시하지 않는다.

필수 지표는 자산 추이·총수익률·실현/미실현 손익·최대낙폭·승률·완료 거래 수·보유 기간·현금 비중·비용이다. 벤치마크 대비 결과와 표본 수를 함께 제공한다. 미도달·누락·미청산 건수를 표시하고 이를 0% 수익이나 성공 거래로 집계하지 않는다.

실험 입력과 결과는 규칙 버전·비용·데이터셋을 포함한 실험 ID로 묶는다. 비용만 바꾸어도 별도 실험으로 생성한다. 원본의 완료 성과 저장 키는 보고서·종목·기간이므로 비교 실험을 그 키로 덮어쓰지 않는다.

기준 전략은 사용자가 선택한 무효화 보유 방식이다. 20거래일 고정 보유와 시장지수 비교는 후속 비교안이며 별도 채택 여부를 확인한다. 비용 비교는 확정 범위이지만 비교 비용값 자체는 실험 가정으로 명시해야 한다. 규칙을 조정한 기간과 그 이후 검증 기간을 구분해 반복 조정의 결과만 보고 전략을 승인하지 않는다.

화면·Telegram은 같은 저장 결과를 조회한다. 실험 시작·중지·생성은 인증된 조작 경로로 구분한다. 원본의 조회 API와 결과를 저장하는 평가 POST의 성격을 보존하고, 화면 조회만으로 결과를 바꾸지 않는다.

## 단계 5 화면 설계

| 화면 | 첫 버전에 표시할 내용 | 주요 조작 |
| --- | --- | --- |
| 요약 | 총자산·수익률·최대낙폭·현금, 자산 추이, 오늘의 매매·무효화·오류, 데이터 기준시각 | 실험 선택, 상세 이동 |
| 후보와 보고서 | 원본 보고서, 최초 추천·반복 횟수, 원래 판정과 실험 편입, 근거·가격·무효화 상태 | 날짜·종목 필터, 보고서 비교 |
| 백테스트 | 기간·비용·규칙·데이터 범위, 실험 비교, 표본·미완료 상태 | 실행 시작, 새 설정의 별도 실험 생성 |
| 모의계좌와 일지 | 보유·현금·손익, 대기·체결·보류 거래, 진입·청산 이유와 연결 보고서 | 거래·보유 구간 상세 이동 |
| 알림과 운영 | 수집·평가 상태, 발송·오류·재시도, 실험 실행 상태 | 일시중지·재개, 운영 이력 확인 |

모바일에서는 요약과 중요 이벤트를 먼저 보여주고 표의 상세를 펼쳐 확인하도록 한다. 차트는 가격·거래량·이동평균과 추천·가상 체결·무효화 시점을 연결한다. 저장 종가와 별도 실시간 관측값은 각각 출처·KST 시각·신선도를 표시한다. 실시간 값으로 저장 보고서나 과거 실험을 덮어쓰지 않는다.

확인 불가·대기·실패를 숫자 0이나 정상 상태로 대체하지 않는다. 공시 자동 무효화 미적용, 비용 가정, 지원 데이터 기간을 눈에 띄게 표시한다. 수동 매수·매도 버튼은 첫 버전에 포함하지 않는다.

접근 방식과 인증은 프로젝트 기반 단계에서 정한다. 새 화면에 서버의 역할 토큰이나 비밀키를 넣지 않는다. Telegram 상세 링크는 로그인 후 정확한 보고서·거래·실험을 열어야 한다. 과거 알림의 링크를 최신 보고서로 일괄 대체하지 않는다.

## 단계 6 지속 운용과 Telegram

거래일 저녁 요약은 계산 완료 여부와 함께 자산·수익률·오늘의 변화·확인 필요 항목을 전달한다. 신규 종목의 가상 매수 체결, 가상 매도 체결, 무효화 확인, 수집·계산 오류를 이벤트로 알린다. 기존 후보가 같은 조건으로 유지됐다는 이유만으로 같은 이벤트를 반복 발송하지 않는다.

무효화 확인과 다음 시가의 매도 체결은 서로 다른 시점과 상태다. 발송 이벤트도 구분하고, 재시도로 같은 이벤트가 두 번 전달되지 않도록 한다. 최초 채널 실검증은 별도로 승인된 시험 대상과 범위에서 수행하며 운영 전환은 로컬 테스트와 구분해 보고한다.

첫 자동 운용에서는 신호 수집·판정·가상 체결·평가·발송을 순서대로 관찰한다. 재시작, 중복 스케줄, 오래된 데이터, 가격 누락, Telegram 실패, 일시중지·재개 시나리오의 실제 증거를 확보한다. 운영 적용과 별도 메시지 발송은 이 계획 작성 요청만으로 실행하지 않는다.
