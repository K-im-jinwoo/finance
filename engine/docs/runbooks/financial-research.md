# 재무 우선 스크리닝과 통합 추천 운영

재무 평가를 가격 이력과 분리하고, DART 확대 수집 → 재무 통과 기업의 과거 뉴스 수집·사건 검토 → 총점 → 다음 거래일 조건부 매수 추천으로 연결한다. 계약은 `UNIFIED_RESEARCH_V1`, 현재 정책은 `unified-research-2026-10-13.1`이다. 사용자의 운영·Telegram 적용 승인에 따라 2026-10-12 운영에 연결했다. `STOCK_UNIFIED_ENABLED=true`인 운영 보고서는 `OPERATING_APPROVED`, 그 외 로컬 실행은 `LOCAL_VALIDATION_PROPOSAL`로 표시한다. 이는 운영 규칙의 승인 상태이며 수익률 검증이나 주문 승인이 아니다. 기존 모의계좌에는 새 순위를 공급하지 않는다.

## 기존 보고서 진단

Finance 저장소 루트에서 실행한다. 원본 DB는 존재해야 하며 읽기 전용으로 연다. 조회는 스키마를 생성하거나 공급자·Telegram을 호출하지 않는다.

```powershell
$taskPython = 'C:\Users\USER\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe'
$env:PYTHONPATH = Join-Path (Get-Location) 'engine\src'
& $taskPython -m stock_assistant.research_cli audit --database '<사용자가 지정한 DB 경로>' --reports 8
```

결과에는 최근 보고서의 판정·경고 코드·추가 확인 항목 수, 자료 기준일과 재무 필드 확보 건수가 있다. 경고를 결격 경고, 자료 부족, 원인 검토, 가격·유동성 등으로 묶는다. 이 분류는 진단용이며 저장된 판정을 변경하지 않는다. 보고서 1~20개만 집계하고 계좌·보유·자격증명은 읽지 않는다. 뉴스 후보의 고정 보류 문구는 별도로 집계한다.

운영 서버 조회가 필요한 경우 기존 SSH 신뢰를 사용하며 명시적으로 승인된 대상과 필드만 조회한다. 서버에 파일을 설치하거나 DB를 마이그레이션하지 않는다.

```powershell
& $taskPython scripts\oracle_screening_audit.py --host '<승인된 기존 SSH 호스트>' --reports 8
```

## 전체 대상 재무 평가

```powershell
& $taskPython -m stock_assistant.research_cli financials --database '<사용자가 지정한 DB 경로>'
```

저장된 전체 종목을 검사한다. 일반기업 보통주는 `PASS`, `VERIFY_PENDING`, `EXCLUDED`로 구분하고 금융회사·다른 자산 유형은 `NOT_APPLICABLE`로 둔다. 기업 유형이 미확인이면 분류 확인 대기로 남기며 일반기업 조건을 임의로 적용하지 않는다. 실제 시장 전체의 재무를 수집한 명령은 아니다.

필수조건은 기존 일반기업 영업이익·연간·TTM 영업이익과 OCF 양수다. 필수 자료가 없거나 TTM이 185일을 초과하거나 같은 결산일의 연간 이익 근거가 충돌하면 확정 점수는 null이다. 확인된 필수조건 실패는 누락보다 먼저 제외한다. 선택 FCF가 없다는 이유로 일괄 보류하지 않는다.

| 비교 항목 | 점수 규칙 |
| --- | --- |
| 영업이익 | 기존·연간·TTM 모두 양수이면 25점 |
| OCF | 양수이면 25점 |
| 3개년 영업이익 | 같은 연결·별도 기준의 연속 3개년 근거가 있고 모두 흑자·기존 5% 허용 범위 안의 유지 또는 개선이면 20점, 모두 흑자지만 약화하면 10점, 과거 적자 포함은 0점 |
| 회전율 | 매출채권·재고자산 두 추세가 기존 5% 허용 범위에서 유지·개선이면 15점 |
| FCF | 0 이상이면 15점, 같은 기업·기간의 공식 성장투자 원인 근거가 연결되면 10점, 원인 미확인 음수이면 0점과 확인 대기 |

선택 지표나 과거 이력이 없으면 해당 가점을 부여하지 않으며 다른 배점을 늘리지 않는다. 없는 값은 0으로 바꾸지 않는다. 결과에 `score_coverage`로 확인 가능한 항목과 최대 배점을 표시한다. 이 점수는 기존 가격 혼합 점수와 다르며 수익 확률이 아니다.

`next_news_review_symbols`는 재무 통과 기업의 점수순 목록이다. 필수 재무 보완은 `financial_fetch_symbols`, 기업 유형 확인은 `classification_review_symbols`에 나타난다. 이 목록은 이후 수집 작업의 입력이며 현재 명령이 외부 수집을 실행하지 않는다.

## 3개년 자료 입력

직접 확보·검증한 공개 재무 표본이 있을 때만 선택적으로 입력한다. 관측시각을 과거로 바꾸지 않는다.

```powershell
& $taskPython -m stock_assistant.research_cli financials --database '<DB 경로>' --annual-history '<검증된 연간 재무 JSON 경로>'
```

JSON은 다음 필드를 가진 배열이다. 종목코드, 14자리 공시 접수번호, 연결·별도 기준, 원문 URL, 실제 공개·관측시각이 필요하다. 정정본은 같은 결산일의 더 늦은 공개·관측 버전으로 연결하며 충돌하는 같은 시점 자료는 오류로 처리한다. 파일은 2 MB, 20,000행 이하로 제한한다.

```json
[
  {
    "symbol": "900001",
    "period_end": "2025-12-31",
    "operating_income": "1000000000",
    "published_at": "2026-03-01T00:00:00+00:00",
    "observed_at": "2026-03-02T00:00:00+00:00",
    "receipt_id": "20260000000001",
    "statement_basis": "CFS",
    "source_url": "https://dart.fss.or.kr/example"
  }
]
```

위 행은 형식 설명을 위한 가상 자료다. 실제 조회·검증된 공시가 아니다. 성장투자 FCF 근거는 평가 함수의 구조화된 입력에서 공식 DART 여부, 해당 종목·기간, 명시적인 원인 사실을 함께 확인한다. 일반 공식 기사나 다른 기업·기간의 근거는 가점을 주지 않는다. 검토 결과는 아래 `import-reviews` 경로로 입력하며 원문을 자동으로 읽어 성장투자라고 확정하지 않는다.

## 별도 연구 기록과 검증 작업

```powershell
& $taskPython -m stock_assistant.research_cli financials --database '<원본 DB 경로>' --state-database '<Git 밖의 별도 로컬 연구 DB 경로>'
```

연구 DB 경로를 명시했을 때만 로컬 상태를 쓴다. 원본과 같은 파일·별칭은 거부하며 기존의 다른 용도 DB에도 쓰지 않는다. 동일 입력과 평가 결과는 같은 평가 ID를 재사용하고, 자료·판정의 변화는 새 기록으로 남긴다. 원본 재무 입력과 규칙 스냅샷을 연구 DB에 보존해 기존 원본의 같은 공시 행이 나중에 수정되어도 과거 연구 근거를 유지한다.

확인 작업은 `OPEN`, 근거 보완 후 `RESOLVED`, 제외·적용 대상 변경으로 불필요해진 경우 `NOT_REQUIRED`로 구분한다. 불필요해진 작업을 검증 완료로 표현하지 않는다. 작업의 생성·변경시각과 연구 기록의 `recorded_at`은 실제 실행시각이며 평가 기준시각 `as_of`와 구분한다. 과거 `as_of`로 과거 관측을 만들어내지 않는다.

기존 재무 스냅샷에는 실제 과거 관측·정정 계보가 불완전할 수 있어 `historical_replay_certified=false`를 유지한다. 새 연구 DB의 실제 확보시각도 그 이전 과거 실행의 증거가 되지 않는다. `paper_account_eligible=false`와 `orders_enabled=false`이며 기존 보고서·CIO 순위·모의계좌에 연결하지 않는다.

## DART 확대 수집

새 입력 DB와 기존 재무 평가 이력 DB는 서로 다른 용도다. `--research-database`는 새 입력 DB이며 원본·기존 상태 DB·뉴스 사용량 DB와 다른 Git 밖의 로컬 경로를 사용한다. 원본 DB에는 종목 목록과 KRX 가격 이력이 있어야 한다. 명령은 자격증명 파일을 읽어 공개 자료를 조회하고 별도 입력 DB에만 저장한다. 운영 서버 경로를 지정해 실행하는 배포 절차가 아니다.

```powershell
$taskSource = '<존재하는 로컬 원본 DB 경로>'
$taskResearch = '<Git 밖의 새 연구 입력 DB 경로>'
& $taskPython -m stock_assistant.research_cli collect-dart --database $taskSource --research-database $taskResearch --api-key-file '<DART 키 파일>' --batch-size 25
```

가격 상위 30개를 입력으로 사용하지 않는다. 상장 일반주 전체에서 최근 시도하지 않은 순으로 회전하며 한 번에 최대 50개, 기본 25개를 처리한다. 확인되지 않은 기업 유형은 DART 기업개황으로 먼저 분류한다. 금융업·12월 결산이 아닌 기업은 별도 평가 대상으로 남긴다. 이 구현이 모든 업종·결산월을 지원한다고 표현하지 않는다.

첫 조회는 10년 공시 검색 범위를 확보하고, 최신 사업보고서 최대 3개 연도와 최신 분·반기 보고서로 TTM을 산출한다. `TTM = 직전 연간 영업이익 + 당기 누적 - 전년 동기 누적`이며 연간·TTM·과거 이력이 전부 CFS이거나 전부 OFS여야 한다. CFS 중간 자료가 없으면 전체 계보를 OFS로 다시 확보한다. OCF·FCF·회전율은 최신 연간 재무 기준이고, TTM 영업이익과 기간을 별도로 표시한다.

접수번호·공개일·연결/별도 기준·실제 최초 관측시각을 보존한다. 공시는 개별 불변 기록으로 저장하고 검색 커서에는 기간·건수·지문만 남겨 매일 10년 원문 목록 전체를 복사하지 않는다. 이미 확보한 접수번호는 재사용하고, 다음 실행은 마지막 검색일 전 7일을 겹쳐 공시 목록을 갱신한다. 정정 접수번호가 바뀐 재무만 다시 조회한다. 같은 날 검색 완료한 회사에는 요청하지 않으며 이후 실패가 발생한 회사는 재시도한다. 기업개황은 7일 캐시한다. `--symbols 005930,000660`로 지정한 표본만 처리하거나 `--force`로 재확보할 수 있다. 어떤 명령도 예약 작업을 생성하지 않는다.

기존 한도인 검색 구간당 50페이지·회사당 500요청을 유지한다. 초과 구간만 날짜로 분할하며 단일 날짜 초과·페이지 변화·부분 실패·접수번호 충돌은 실패한다. 실행당 요청은 기본 2,000회, 최대 5,000회다. 실패한 회사의 검색 완료일은 전진하지 않고, 인증 오류·429는 배치를 중단한다. 일부 회사가 실패한 명령은 JSON 결과를 출력하고 종료 코드 1을 반환한다. 완료된 다른 회사의 확보 자료는 유지한다.

## 재무 통과 기업 뉴스와 원문 검토

```powershell
& $taskPython -m stock_assistant.research_cli collect-news --database $taskSource --research-database $taskResearch --client-id-file '<Naver ID 파일>' --client-secret-file '<Naver secret 파일>' --usage-database '<기존 공유 뉴스 사용량 DB>' --limit 5
& $taskPython -m stock_assistant.research_cli review-queue --database $taskSource --research-database $taskResearch
```

뉴스 조회는 재무 `PASS`이면서 F≥70인 기업만 대상으로 한다. 최근 조회하지 않은 기업부터 최대 5개 이름을 검색하고, 제목의 기업명 일치를 확인한다. 현재 검색 결과는 `BOUNDED_RECENT_SEARCH`로 남긴다. 기존 하루 20회·월 500회·1시간 쿨다운·공식 무료 정책 확인을 그대로 사용하며 사용량 원장을 새로 만들거나 재설정하지 않는다.

`review-queue`에는 재무 점수·부족한 항목, 위험 원문 URL, 최근 재료 원문, 공시 검색 기록 ID, 아카이브 ID와 필요한 검토 기간이 나온다. 제목 신호는 검토 대상을 찾는 데 사용하며 범죄 확정이나 긍정 가점으로 승격하지 않는다. 일반 기사에 `official=true`를 붙이는 방식으로 검토를 대신하지 않는다.

자동 과거 수집은 아래 `collect-archive`와 운영 주기에 연결되어 있다. [Naver 공식 뉴스 검색 명세](https://api.ncloud-docs.com/docs/naver-api-hub-search-news)의 시작 위치는 최대 1,000이며, 색인에 없는 기사와 이를 넘는 결과를 가져오는 별도 공급자는 없다. 사용자는 추가 아카이브를 사용하지 않는다고 확인했다. 조사 미완료는 `NEWS_HISTORY_COVERAGE_UNAVAILABLE` 확인 대기로 남긴다. `import-reviews` 문서는 실제 근거를 입력하기 위한 계약이며, 아래 예시 필드를 가상 값으로 채워 검토 완료를 만들어서는 안 된다.

```powershell
& $taskPython -m stock_assistant.research_cli collect-archive --database $taskSource --research-database $taskResearch --client-id-file '<Naver ID 파일>' --client-secret-file '<Naver secret 파일>' --usage-database '<기존 공유 뉴스 사용량 DB>' --pages 5
```

기업명 검색을 날짜순으로 최대 5페이지씩 읽고 커서를 저장한다. 다음 조회에서 마지막 행을 겹쳐 읽어 색인 이동을 확인한다. 미완료 기업을 새 기업보다 먼저 처리하고, 기준 기사가 다음 페이지의 다른 위치에 있어도 이어간다. 페이지 전체가 기준 기사보다 새로우면 같은 예산·검색 위치 제한 안에서 다음 페이지를 탐색한다. 기준 행이 사라지거나 순서 연결을 확인할 수 없으면 처음부터 재시작한다. 기준 행이 제공 범위 밖으로 밀려난 경우에도 완료로 처리하지 않는다. 미완료 기준 조사는 날짜가 바뀌어도 기존 종료일을 유지해 이어간다. 3년 이전까지 도달하거나 실제 결과를 소진한 경우에만 `COMPLETE`이며, 범위는 **`NAVER_INDEXED_QUERY_RESULTS`**다. 이는 모든 언론사의 전체 기사 확보 인증이 아니다. 시작 위치 1,000에 막히면 `PROVIDER_LIMIT`이며 중립 뉴스 점수를 부여하지 않는다. 같은 한도 조회는 7일 재시도 간격을 두어 새 조사 예산을 계속 소모하지 않는다.

한도에 막힌 기업에는 횡령·배임·유상증자·전환사채·계약해지 5개 위험 검색을 별도 예산 안에서 보완한다. 해당 검색 결과는 기업 연관성이 미검증인 조사 근거로 보존한다. 이 좁은 검색 완료는 `material_coverage`이며 전체 뉴스 `news_coverage`를 대신하지 않는다. 기존 하루 20회·월 500회·1시간 쿨다운을 유지하며 실패·미사용 예약을 환불하거나 원장을 재설정하지 않는다.

한 위험 검색이 한도에 막혀도 나머지 검색은 계속한다. 모든 보완 검색이 완료되거나 한도에 도달한 기업 때문에 다른 기업의 뉴스 조회가 멈추지 않도록 다음 조사로 넘어간다. 한도에 도달한 자료는 여전히 전체 조사 미완료다.

공식 계약 공시는 [DART 공시 원문 ZIP](https://opendart.fss.or.kr/guide/detail.do?apiGrpCd=DS001&apiId=2019003)의 구조화된 계약명·상대방·금액·매출 대비 비율·기간을 확인해 자동 사건으로 연결한다. 실제 XHTML 표와 `TE` 셀을 지원한다. 불완전·상충 값, 비정상 날짜, XML entity와 크기 초과 문서는 자동 가점을 주지 않는다. 정정·취소는 같은 사건에 연결해 중복 가점을 방지한다. 횡령·배임 등의 제목만으로 범죄나 강한 결격을 확정하지 않으며, 해당 위험의 원문 검토가 남으면 확인 대기를 유지한다. 공식 명세 확인일은 2026-10-12 KST다.

```powershell
& $taskPython -m stock_assistant.research_cli import-reviews --database $taskSource --research-database $taskResearch --review-file '<원문 검토 JSON>'
```

JSON 최상위에는 `archives`, `events`, `coverage`, `fcf_reviews` 배열만 사용하며 각각 1,000개, 파일 전체 5 MB 이하다. 빈 배열은 생략할 수 있다. 한 문서의 검증을 모두 마친 뒤 한 트랜잭션으로 저장한다. 아카이브를 먼저 입력해 반환된 ID를 다음 coverage 문서에서 참조한다. 필드 계약은 다음과 같다.

| 입력 | 필수 내용 |
| --- | --- |
| `archives` | `symbol`, `start`, `end`, `search_description`, 실제 검색 완료 여부 `search_complete`, `evidence` 배열 |
| `events` | `symbol`, 같은 사건의 안정된 `event_id`, `category`, `direction`, `state`, `materiality`, boolean `verified`·`hard_exclusion`, `announced_at`, `reviewed_at`, 긍정 사건의 `valid_until`, `reviewer`, `rationale`, `evidence` |
| `coverage` | `symbol`, `start`, `end`, `observed_at`, `reviewed_at`, `status=REVIEWED`, `sources=[NEWS_ARCHIVE,DART_HISTORY]`, 해당 기업의 실제 아카이브·공시 기록 ID 배열 `source_refs`, `reviewer` |
| `fcf_reviews` | `symbol`, `reviewer`, `rationale`, 해당 기업·기간·성장투자 원인이 명시된 `evidence` |
| 각 `evidence` | `source_type`, `title`, `url`, 실제 `published_at`·`observed_at`, boolean `official`, `facts` 배열 |

사건 분류는 `CONTRACT`, `APPROVAL`, `POLICY`, `EARNINGS`, `DILUTION`, `MANAGEMENT`, `BUSINESS_DAMAGE`다. 방향은 `POSITIVE/NEGATIVE/NEUTRAL`, 상태는 `ACTIVE/RESOLVED/CANCELLED`, 규모는 `LOW/MEDIUM/HIGH`다. VERIFIED 사건은 DART·KIND·법원 공식 원문과 검토자·판단 근거가 필요하며, 해당 공식 원문의 검토 사실에 `ISSUER:<해당 종목코드>`를 명시한다. 다른 기업 원문은 가점 근거로 사용할 수 없다. 같은 공식 근거와 분류를 다른 사건 ID로 중복 점수화하면 오류가 된다. 해소·취소로 상태를 바꾸려면 이전 검토보다 새로운 공개 원문이 필요하다. 원본 검토 기록은 유지한다.

coverage는 최소 3년 뉴스 검색 완료 기록과 10년 DART 검색 완료 기록의 실제 ID와 기간을 검증한다. 마지막 검토는 7일 이내이고 검색 종료일은 직전일까지여야 한다. 미해소 위험은 이 기간보다 오래되어도 사건 원장에서 계속 반영한다. 이미 검토한 원문도 다른 사건 분류의 위험을 자동으로 숨기지 않는다. 새 악재 제목을 발견하면 해당 사건을 검토하기 전까지 확인 대기로 둔다.

FCF 근거의 `facts`에는 `FCF_NEGATIVE_DUE_TO_GROWTH_INVESTMENT`, `ISSUER:<종목코드>`, `FCF_PERIOD_END:<연간 결산일>`이 필요하다. 다른 기업·기간이나 일반적인 투자 기사에는 성장투자 가점을 부여하지 않는다. 모든 입력의 실제 DB 기록시각을 남기며 과거 기준일을 입력시각으로 소급하지 않는다.

## 총점과 조건부 매수 추천

휴장일을 추측하지 않도록 기존 Toss 시장 캘린더 어댑터로 완료된 정규장 거래일을 확인한다. 단독 `collect-calendar`는 이미 발급된 보호된 토큰 파일을 사용한다. 운영 `refresh-unified`는 설치된 공유 인증 어댑터와 기존 캐시·잠금·갱신 경로를 사용하며 별도 OAuth 경로로 우회하지 않는다. 같은 Client ID의 새 토큰 발급이 기존 토큰을 무효화하는 [공식 인증 계약](https://openapi.tossinvest.com/openapi-docs/latest/openapi.json)을 보존한다. 공식 명세 확인일은 2026-10-12 KST다. 주문 API는 사용하지 않는다.

```powershell
& $taskPython -m stock_assistant.research_cli collect-calendar --database $taskSource --research-database $taskResearch --token-file '<이미 발급된 보호된 토큰 파일>'
& $taskPython -m stock_assistant.research_cli recommend --database $taskSource --research-database $taskResearch --format text --save-report
```

`--format json`은 전체 평가·제외·확인 대기 사유와 근거 ID를 출력한다. `--save-report`는 새 계약 보고서만 별도 입력 DB에 기록한다. 원본 보고서 테이블에는 쓰지 않는다. 같은 기준시각과 입력은 같은 보고서 ID를 만든다.

뉴스 N은 검토 완료된 검색의 중립 50점에서 시작한다. 검증된 유효 긍정 사건은 규모별 5/10/20점, 사업 악재는 5/10/20점 감점하며 0~100으로 제한한다. 재무 점수와 중복되는 긍정 실적 기사는 가점을 주지 않는다. 희석·경영 위험은 R에만 규모별 5/10/20점, 합계 최대 30점을 적용한다. 기사 건수나 재전송 횟수는 점수에 사용하지 않는다.

`S = clip(0.7F + 0.3N - R, 0, 100)`이며 현재 적용 임계값은 F≥70·S≥75다. 점수만으로 매수를 결정하지 않으며 판정 우선순위는 다음과 같다.

1. 재무 필수조건 실패·검증된 강한 위험이면 `EXCLUDED`.
2. 핵심 재무·과거 사건 검토·공시 갱신·가격 이력이 부족하면 `VERIFY_PENDING`.
3. 점수·기존 가격 진입 조건·유동성 조건을 충족하지 못하면 `WATCH`.
4. 모두 충족하면 `BUY_RECOMMENDATION`, 화면 문구는 **매수 추천 (다음 거래일 조건부)**.

가격은 최소 61일 이력, 캘린더가 확인한 완료된 거래일 일봉, 기존 반등 또는 모멘텀 조건과 20일 평균 거래대금 10억 원 기준을 사용한다. 장 마감 전에는 직전 거래일을 사용하고, 달력 `regularMarket.endTime`이 지난 뒤에는 당일 일봉을 요구한다. 새 운영 주기는 `refresh-daily --include-completed-today`로 공식 마감시각 이후에만 당일 KRX 자료를 확보한다. 기존 명령의 기본 동작은 유지한다. 당일 자료가 아직 미공개이면 오래된 자료로 준비 완료를 표시하지 않는다. 장중 즉시 진입을 권하지 않고 다음 장 최신 시세로 다시 확인하는 조건을 명시한다. 현재 날짜의 캘린더가 없거나 KRX 가격일이 맞지 않으면 확인 대기다. 회전율 약화 같은 참고 경고가 하나 있다는 이유만으로 일괄 보류하지 않는다.

최종 추천·관찰을 한 목록으로 점수순 정렬하며 최대 5개, 부족하면 0~4개만 반환한다. 확인 대기·제외를 수 채우기에 사용하지 않는다. 기존 보고서·가격 점수·판정 enum·모의계좌 소비자를 보존한다. 새 조회 API는 `GET /v1/unified/reports/latest`와 `GET /v1/unified/reports/UR-...`이며 CIO·scheduler·전문가의 기존 역할 인증을 사용한다. 조회는 별도 입력 DB를 읽기 전용으로 연다. 구버전 `R-...` 보고서와 새 `UR-...` 보고서를 섞지 않는다.

## 운영 주기와 Telegram

아침·저녁·주간 작업은 기존 일정·수신처를 유지한다. 일봉 갱신 후 DART 25개 회전 수집, 예산 안의 뉴스 5페이지, 공식 계약 최대 5개 검토, 공유 캘린더 확인과 통합 보고서 저장을 실행한다. 재무 원문은 접수번호가 같으면 재사용한다. Naver 쿨다운이면 기존 자료를 사용하고 미완료 범위를 표시한다. Telegram 작업은 `no_agent=true`로 스크립트의 점수·판정을 직접 전달해 모델이 모든 종목을 고정 보류 문구로 바꾸지 않는다. 장중 거래량 경고 작업은 비활성화했다. 수동 실시간 조회 경로는 유지한다.

2026-10-13 보완에서는 뉴스 조사 중이거나 뉴스 범위가 확인된 기업을 기존 25개 배치 안에서 최대 5개 우선 갱신한다. 나머지 배치는 기존 전체 대상 회전에 사용한다. 매일 재무제표를 재수집하는 대신 공시 목록에서 새 접수번호·정정 여부를 확인하고 재무 원문 캐시를 재사용한다.

새 운영 주기만 `--allow-unpublished-latest`를 사용한다. 공식 캘린더가 확인한 최신 거래일의 KRX 응답이 비어 있으면 연구 주기에서는 가격 확인 대기로 기록하고 DART·뉴스 조사와 점수 계산을 계속한다. 원본의 가격 준비 상태는 기존 `FAILED` 계약을 유지하며 새 연구 상태만 `VERIFY_PENDING`이다. 과거 공백·인증 오류·전송 실패는 이 예외에 포함하지 않는다. 새 보고서는 현재 날짜·필요한 거래일·`READY` 가격 확인을 검증하고, 미확인 상태이면 점수가 충분해도 `PRICE_REFRESH_UNVERIFIED`로 매수 추천을 차단한다. Telegram에는 가격 기준일, 재무 70점 이상 검토 대상 수, 뉴스 점수 확보 수와 한국어 부족 사유가 표시된다. 제외·별도 평가 대상의 확인 항목을 검증 대기 집계에 섞지 않는다.

`scripts/oracle_unified_rollout.py`의 단계는 `stage → validate → deploy`다. staging은 기존 런타임 설정과 SQLite 온라인 백업을 서버의 보호된 백업 폴더에 남긴다. validate는 읽기 전용 원본 스냅샷, 실제 DART·공유 캘린더와 기존 뉴스 사용량 원장을 사용하고 연구 입력만 별도 DB에 기록한다. 배포는 실제 컨테이너의 mount·port·user·공유 인증·역할 인증·네트워크를 보존하고 health·주문 비활성 및 mount/port 일치를 확인한다. 실패하면 이전 컨테이너·current 링크·변경한 설정으로 복구하며 기존 이미지와 원본을 삭제하지 않는다.

```powershell
# 사용자에게 운영 변경이 승인된 실행에서만 사용한다.
& $taskPython scripts/oracle_unified_rollout.py stage --stamp '<UTC 릴리스 ID>'
& $taskPython scripts/oracle_unified_rollout.py validate --stamp '<동일 ID>'
& $taskPython scripts/oracle_unified_rollout.py deploy --stamp '<동일 ID>'
& $taskPython scripts/oracle_unified_verify.py
# 필요 시 동일 릴리스의 기존 컨테이너·설정을 복구한다.
& $taskPython scripts/oracle_unified_rollout.py rollback --stamp '<동일 ID>'
```

## 검증과 운영 적용 경계

새 테스트는 가격 이력 없는 재무 평가, 필수 값의 0·음수, 선택 지표 누락, 185일 경계, 미래·충돌·유형 혼합 자료, 원본 DB 불변, 평가 재사용, 확인 작업의 완료·불필요 구분과 CLI 실패 처리를 확인한다. 변경 후 Finance 루트의 전체 검증 명령을 사용한다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/verify.ps1 -Python $taskPython
```
