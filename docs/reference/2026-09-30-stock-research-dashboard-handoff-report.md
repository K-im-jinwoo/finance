# 주식 리서치 대시보드 인수인계 보고서

작성 기준: 2026-09-30 KST

대상: 새 프로젝트에서 백테스트와 자동 모의투자 대시보드를 이어서 설계하고 구현할 담당자

실행 계획: [주식 리서치 대시보드 구현 계획](../superpowers/plans/2026-09-30-stock-research-dashboard-handoff-plan.md)

이 프로젝트의 목표는 현재 주식 후보 선정과 가격·재무 무효화 규칙이 어떤 성과를 내는지 검증하는 것이다. 사용자는 자동 모의계좌만 운영하고, PC와 휴대폰에서 상세 내용을 확인하며, Telegram 알림에서 해당 상세 화면으로 이동하는 구성을 선택했다.

동일 종목이 반복 추천되는 현상은 저장 보고서에서 확인됐다. 논리와 순위가 유지되는 후보의 반복 등장은 허용하며, 이를 매번 새로운 매수로 처리하지 않는다. 첫 버전은 후보를 강제로 순환시키기보다 신규·유지·재검토·무효화를 구분하고, 실제 가상 거래와 성과를 연결하는 데 집중한다.

왕복 0.3%는 사용자가 선택한 실험 가정이다. 실제 증권사의 수수료·세금·슬리피지를 확인한 값으로 표현하면 안 된다. 첫 버전은 공시 무효화를 모두 자동 적용한 전략으로도 표현하면 안 된다.

## 반복 추천 조사에서 확인한 사실

이 대화에서 사용자의 명시적 승인을 받은 뒤 운영 SQLite를 `mode=ro`로 열어 최근 최대 40개 보고서의 기준시각·종목명·종목코드·점수·검토등급을 조회했다. 실제 조회 대상은 22개 저장 보고서였으며, 과거 테스트·초기 데이터와 후보 수가 다른 보고서도 포함돼 있었다. 전체 건수를 사용자에게 발송된 일일 추천 횟수로 간주해서는 안 된다.

이 표는 저장 보고서의 스냅샷이다. 이 조회로 Telegram 실제 수신, 같은 기간의 가격·공시 갱신 여부, 현재 전체 종목의 동점 분포까지 검증한 것은 아니다. 이 기록을 현재 투자 권고로 재사용하지 않는다.

확인된 선정 함수는 `검토등급 → 점수 내림차순 → 종목코드` 순서로 정렬한 뒤 상위 종목을 선택한다. 이전 추천 이력은 정렬에 사용하지 않는다. 동일 입력에서 같은 5종목이 반복되고, 동점에서는 종목코드가 작은 종목이 우선되는 동작을 로컬에서 재현했다.

무효화 조건은 현재 보고서의 설명문 필드다. 가격 조건이 사라져 `BUY_HOLD`로 바뀌어도 선정 함수는 `EXCLUDED`만 제외하므로 보고서에 계속 포함될 수 있다. 후보 유지, 무효화 판정, 가상 청산은 각각 명시적으로 구현해야 한다.

## 다음 프로젝트에서 먼저 다룰 구현 차이

1. **오전 신호의 당일 시가 진입**: 기존 성과 계산은 보고서 시각을 KST 날짜로 줄이고 `trade_date > signal_date`인 가격을 사용한다. 선택한 새 규칙은 장 시작 전 신호의 당일 시가도 허용하므로, 신호 생성·데이터 가용·거래 가능 시각을 구분하는 새 체결 규칙이 필요하다.
2. **무효화 청산**: 설명문을 생성하는 것과 조건을 판정해 가상 청산하는 것은 별개다. 보유 중인 모든 모의 포지션을 후보 순위와 무관하게 점검해야 한다.
3. **장중 감시 대상**: 기존 `watch_symbols()`는 저장 보유종목과 최신 보고서의 후보를 합친다. 새 모의 포지션을 기존 실제 보유 원장에 넣지 말고, 모의계좌의 전체 보유종목을 별도로 관리·점검해야 한다.
4. **실험별 결과 보존**: 기존 완료 성과는 불변이고 저장 키는 보고서·종목·기간이다. 비용·청산·체결 규칙이 다른 비교 실험은 별도의 실험 ID와 저장 구조가 필요하다.
5. **추천과 거래의 중복 구분**: 동일 종목의 반복 보고서는 하나의 보유 구간과 연결한다. 보고서마다 추가매수하거나 하나의 거래를 여러 성공 표본으로 세면 안 된다.
6. **관측 데이터와 과거 재현**: 현재 확보한 데이터와 최신 재무를 과거 시점에서 이용 가능했던 데이터로 간주하지 않는다. 정정 공시, 당시 종목 구성, 분할·배당·거래정지 처리 범위를 조사해야 한다.

`ranked_symbols()`도 같은 선정 함수를 사용하고 DART 수집 대상 선정에 연결된다. 첫 버전의 범위는 현재 추천 규칙 검증이다. 후보 다양성을 이유로 공통 정렬이나 수집 대상을 임의로 바꾸지 않는다.

## 인수인계 방법과 작업 경계

보고서와 실행 계획 두 파일을 함께 새 프로젝트에 전달하면 설계 결정을 이어받을 수 있다. 원본 구현을 재사용하려면 소스·테스트의 현재 상태도 별도로 확인해야 한다. 비밀키·인증 파일·운영 보유정보·운영 DB·원본 로그·가상환경을 전달 자료에 묶지 않는다.

이번 요청에서는 문서를 작성했다. 새 프로젝트 생성, 파일 이동, 타 프로젝트 메시지 전송, 커밋·푸시·배포·운영 DB 변경·실제 Telegram 발송은 수행하지 않았다. 이 문서를 운영 변경에 대한 승인으로 해석하지 않는다. 원본 [AGENTS.md](../../AGENTS.md)와 [기존 요구사항](../superpowers/specs/2026-09-21-hermes-stock-investment-assistant.md)을 함께 검토한다.
