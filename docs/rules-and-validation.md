# 운용 규칙과 검증 명세

기준: 2026-09-30 KST. 인수인계 확정과 이번 사용자 답변을 보존합니다. 아래 **제안**을 사용자 확정 규칙으로 승격하지 않았습니다. 실험 설정에는 `policy_status=LOCAL_VALIDATION_PROPOSAL`과 제안 목록이 저장됩니다.

| 구분 | 명세 | 상태 |
| --- | --- | --- |
| 대상 | 원본 최종 선정 중 PRIORITY_REVIEW. BUY_HOLD도 실험 편입하며 원본 판정은 보존 | 보고서의 구현 기준안, 전체 우선 검토로 확장하지 않음 |
| 자금/비중 | 1천만원, 진입 시 총자산 20%, 최대 5종목. 반복 추천 추가매수/일별 리밸런싱 없음 | 사용자 확정 |
| 수량/현금 | 정수 주식. 매수비용을 포함한 20% 예산으로 수량 계산. 목표 수량 비용만큼 현금이 없으면 편입 보류 | 이번 사용자 답변 확정 |

| 중지 | 대기 거래 취소, 데이터 점검/평가는 계속. 재개 후 새 보고서·새 판정으로만 거래 생성. 과거 시가 소급 없음 | 이번 사용자 답변 확정 |

| 재진입 | 마지막 무효화의 모든 원인에 대해 새 가용 데이터로 해소 입증 후 새 우선 검토 재선정 | 사용자 확정, 각 증거 ID·가용시각 연결 방식은 구현 명세 |
| 공시/추가 종료조건 | 공시 자동 무효화 미적용, 확인 필요. 별도 손절·익절 없음 | 사용자 확정 |
| 결과/비교 | 설정 변경은 새 실험, 이전 결과 보존. 10/60bps는 비용 민감도 가정이며 30bps와 별도 저장 | 비용 비교는 확정, 비교값은 명시한 실험 가정 |

로컬 검증에 적용한 **미확정 구현 제안**:

- 가격 경계는 `종가 < 당일 최신 SMA20`, 정확히 같으면 가격 무효화 아님. 종가 20개에 현재 종가도 포함합니다. 원본의 “아래로 이탈” 문구에 따른 제안입니다. `<`와 `<=` 중 사용자가 확정한 결과로 표현하지 않습니다.
- 체결 비용은 Decimal로 계산 후 원 단위 HALF_UP. 20% 예산을 넘지 않도록 수량을 다시 확인합니다. 소수 금액 보존 방식과의 차이는 큰 수량의 비용 합계에서 원 단위 오차이며 현재안은 원장 검산이 단순합니다.
- 같은 시가에서는 매도 후 매수, 배정 총자산은 해당 시가의 거래 전 현금+보유 평가금액으로 한 번 고정합니다. 비용을 제외한 자산은 매수 체결의 미래 종가를 쓰지 않습니다. 보유 시가가 누락되면 신규 배정은 보류합니다.
- 목표 예산으로 정한 수량의 매수원금+반올림 비용이 현금을 넘을 때 보류합니다. 현금에 맞춰 수량을 줄이지 않습니다. 매수비용을 20% 밖에 추가하지 않습니다.
- 종료는 마지막 유효 평가만 보존하고 열린 포지션을 강제 청산하지 않습니다. 종료 청산 비교는 미채택입니다.
- 기업행위가 없는 일관된 원시가격 구간만 현재 계산 검증 대상으로 삼습니다. 분할·배당·수량 조정을 지원한 것으로 표시하지 않습니다.

체결 시각:

`신호 생성시각 >= 모든 선정 입력의 가용시각`이어야 합니다. `대기 거래 생성시각 < 검증된 세션 open_at`일 때만 해당 시가에 체결합니다. 08:30 신호는 그날 09:00 거래 시가, 20:00 신호는 이후 최초 세션 시가를 사용합니다. 09:00 정각 또는 장중 신호는 이미 지난 시가를 쓰지 않습니다. 시가·달력 출처와 관측시각을 함께 기록하고, 휴장/정지/누락이면 체결 없이 대기 사유를 남깁니다. 세션 시가의 실제 관측이 지연되는 경우와 수집 지연 체결은 실제 공급자 검증 전에 별도 확인해야 합니다.

무효화 구조:

| 코드 | 입력/연산 | 결과 |
| --- | --- | --- |
| PRICE_LT_SMA20 | 최신 가용 종가 20개, 동일 가격 보정 기준, 신선한 자료, `close < average(closes[-20:])` | VALID / INVALID / UNKNOWN |
| GENERAL_FINANCIAL | 일반기업에만 운영·연간·TTM 영업이익과 OCF 양수. 원본 OPERATING_LOSS/OCF_NON_POSITIVE 매핑 | 확인된 필수 수치가 `<=0`이면 INVALID, 누락/오래됨/기간 미검증은 UNKNOWN |
| GENERAL_FINANCIAL (금융/ETF) | 일반기업 조건을 적용하지 않음 | NOT_APPLICABLE. 업권별 임계값 미결정 |
| DISCLOSURE | 정정·취소·실적 훼손의 상세 확인 | REVIEW_REQUIRED. 자동 매도 발생 안 함 |

모델이 보고서 문구를 해석해 청산하지 않습니다. 판정은 데이터·조건코드·증거 ID·가용시각·확인시각을 연결합니다. 누락·오래됨은 무효화와 구분합니다. `fresh`, `periods_verified`는 현재 합성 fixture의 입력 전제입니다. 실제 어댑터는 거래일/재무 기간과 원문을 대조해 이 값을 산출해야 하며 단순 플래그를 실제 확인 증거로 인정하지 않습니다. 원본의 TTM 185일 경고와 원본 공개시각 경계도 실제 입력에 반영해야 합니다.

재진입에는 무효화 원인의 증거 ID와 다른 자료, 마지막 무효화 이후의 가용시각, 모든 해당 원인의 VALID, 그 이후의 PRIORITY_REVIEW 보고서가 필요합니다. 같은 스냅샷은 재진입하지 않습니다. 해소되지 않은 원인을 새로운 일부 판정으로 덮어 지우지 않습니다.

원장과 실행:

자산=현금+보유 평가액, 실현손익=매도 순유입-매수 원금-매수비용, 미실현손익=보유 평가액-남은 취득 총비용입니다. 왕복 비용을 수익률에서 다시 차감하지 않습니다. 완료 승률은 청산된 보유 구간만 집계하고 반복 보고서·미청산을 성공 표본에 넣지 않습니다. 자산 가격이 누락되면 null/확인 불가입니다. MDD는 유효 평가 관측 시점의 고점 대비 하락이며 장중 최대낙폭을 주장하지 않습니다.

실험 ID는 데이터셋 해시·규칙 스냅샷·비용과 생성 nonce에 연결됩니다. SQLite BEGIN IMMEDIATE 안에서 사건 처리·체결·현금·이벤트·커서를 함께 저장합니다. 중복 사건 ID의 같은 입력은 무시, 바뀐 입력은 오류입니다. 오류 시 그 사건의 거래와 커서 변경은 rollback합니다. 사용자 PAUSED와 계산 FAILED를 구분합니다. 조회 GET은 계산/저장 작업을 호출하지 않습니다.

Telegram은 현재 DRAFT_ONLY 원장과 상세 링크 생성까지입니다. 저녁 요약은 거래일당 한 건, 무효화와 매도는 서로 다른 사건입니다. 실제 발송 재시도/중복 전달 보장은 미구현입니다. 외부 발송에서는 Telegram의 응답이 유실된 경우 정확히 한 번 전달을 보장할 수 없으므로 발송 결과/재시도 정책을 별도 설계·승인해야 합니다.
