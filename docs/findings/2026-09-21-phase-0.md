# Phase 0 Findings

기준 시각: 2026-09-21 KST

상태: 읽기 전용 확인 완료. 운영 설정 변경 없음.

## 1. Oracle 현황

- 호스트: Ubuntu 24.04.4 LTS, arm64, Docker 29.6.1, Compose 5.3.1.
- 자원: 메모리 약 11 GiB, 가용 약 10 GiB, 디스크 약 35 GiB 여유.
- 실행 중인 관련 컨테이너는 `deploy-hermes-gateway-1`과 `deploy-wiki-agent-1`이다.
- `deploy-hermes-gateway-1`의 실제 프로세스는 `python /app/telegram_gateway.py`다.
- 호스트와 컨테이너에 공식 `hermes` CLI가 없고, 9119 포트의 Hermes dashboard/serve도 없다.
- 따라서 현재 서비스는 Hermes Desktop이 연결할 수 있는 공식 Hermes 백엔드가 아니라 자체 Telegram-Codex/Antigravity 게이트웨이다.
- 현재 게이트웨이는 기존 WIKI Agent와 같은 Docker private network를 사용하며 Telegram long polling을 수행한다.

## 2. Desktop 연결 결정

- 공식 Hermes Desktop은 로컬 백엔드를 실행하거나 원격 `hermes dashboard`/`hermes serve` 백엔드에 연결한다.
- Telegram gateway는 Desktop 연결 대상이 아니며 별도 프로세스다.
- Oracle에는 공식 Hermes를 별도 서비스로 설치해야 한다.
- 첫 연결은 공개 9119 노출 대신 SSH 연결 또는 Tailscale 사설 주소를 사용한다.
- 공식 문서: https://github.com/NousResearch/hermes-agent/blob/main/website/docs/user-guide/features/web-dashboard.md
- Desktop 문서: https://github.com/NousResearch/hermes-agent/blob/main/website/docs/user-guide/desktop.md

## 3. 프로필과 멀티에이전트

- Hermes profile은 각자 `config.yaml`, `.env`, `SOUL.md`, skills와 session state를 가질 수 있다.
- Desktop에서 프로필별 원격 호스트를 지정할 수 있다.
- `delegate_task` child는 격리 문맥과 별도 terminal session을 가지지만 부모의 허용 toolset을 상속한다.
- 개별 분석 역할의 명확한 권한 분리는 네 개 profile로 만들고, 일시적 병렬 검토는 CIO profile의 delegation으로 실행한다.
- Subagent는 장기 상주 직원이 아니므로 회사 조직도처럼 보이게 만드는 UI와 실제 독립 권한을 혼동하지 않는다.
- 공식 문서: https://github.com/NousResearch/hermes-agent/blob/main/website/docs/user-guide/profiles.md
- 위임 문서: https://github.com/NousResearch/hermes-agent/blob/main/website/docs/user-guide/features/delegation.md

## 4. 기존 게이트웨이 상태

- 로컬 소스의 `stock_tool.py`는 삼성전자·SK하이닉스·미국주식의 고정 예시값만 반환한다. 실제 데이터가 아니다.
- stock intent는 사용자 입력 종목을 전달하지 않고 삼성전자를 고정 호출한다.
- Oracle 이미지의 Antigravity 경로는 `agy` binary와 `GEMINI_API_KEY`를 사용한다. 구독만으로 추가 비용이 0원이라고 확인된 상태가 아니다.
- Oracle 이미지의 Codex 도구는 Windows `cmd.exe` 호출을 전제로 하므로 Linux 컨테이너에서는 작동하지 않는다.
- 이 두 경로는 주식 판단 엔진의 필수 의존성으로 사용하지 않는다.

## 5. 공식 데이터 경계

### KRX

- KRX Open API는 KOSPI·KOSDAQ 주식과 ETF의 종목 기본정보 및 일별매매정보를 제공한다.
- 무료 인증키 신청이 필요하다. 공개 통계 API는 장중 실시간 알림의 근거로 사용하지 않는다.
- 공식 서비스 목록: https://openapi.krx.co.kr/contents/OPP/INFO/service/OPPINFO004.cmd

### DART

- OpenDART는 공시 검색, 공시 원문, 정기보고서 재무정보, 주요사항보고서와 증권신고서 정보를 제공한다.
- 무료 인증키가 필요하다.
- 공식 소개: https://opendart.fss.or.kr/intro/main.do
- 공시 검색 계약: https://opendart.fss.or.kr/guide/detail.do?apiGrpCd=DS001&apiId=2019001

### 토스증권

- 2026-09-21 현재 공식 Open API가 REST와 WebSocket을 통해 국내·미국 시세, 종목정보, 계좌, 보유자산과 주문 기능을 문서화하고 있다.
- 토스증권 계좌가 있는 사용자가 OAuth client credential을 발급해야 한다.
- MVP에서는 시세와 보유자산의 읽기 전용 후보일 뿐 주문 endpoint를 등록하지 않는다.
- 공식 문서: https://developers.tossinvest.com/

### 미래에셋증권

- 공개 검색에서 미래에셋증권 국내주식 계좌용 공식 개발자 API를 확인하지 못했다.
- `digitalx.miraeasset.com`은 미래에셋 계열의 가상자산 API이며 국내 증권 계좌 API로 사용하면 안 된다.
- MVP에서는 미래에셋 보유정보를 수동 입력한다.

## 6. 인증과 비용

- KRX와 DART는 인증키가 필요하다.
- 토스증권 연동은 사용자 계정에서 발급한 OAuth client credential이 필요하다.
- 현재 Oracle의 Antigravity는 Gemini API key를 사용하므로 사용량 과금 여부를 별도로 확인해야 한다.
- ChatGPT 구독을 서버 애플리케이션 API 호출 권한으로 간주하지 않는다.
- 초기 MVP는 외부 LLM 없이도 계산·스크리닝·백테스트가 동작해야 한다.

## 7. 충돌과 게이트

- 현재 Hermes gateway 로컬 worktree에는 일정 선택 기능의 미커밋 변경이 있다. 주식 구현에서 해당 파일을 직접 수정하지 않는다.
- 현재 운영 Telegram receiver를 변경하지 않는다.
- 공식 Hermes 설치, 9119 서비스, Tailscale, API credential 등록, 테스트 Bot 연결, WIKI writer 활성화, DB 배포는 모두 별도 운영 승인 대상이다.
- 장중 거래량 급증 알림은 Toss read-only WebSocket 또는 다른 공식 실시간 공급자가 구성되기 전까지 `사용 불가`로 표시한다.

## 8. Phase 0 결론

로컬 구현은 진행 가능하다. 운영 연결에 필요한 미충족 입력은 KRX key, DART key, 선택적 Toss key, 테스트 Telegram Bot, 공식 Hermes 인증 방식이다. 이 값이 없어도 fixture 기반 Phase 1~2와 profile/API 초안은 구현하고 검증할 수 있다.
