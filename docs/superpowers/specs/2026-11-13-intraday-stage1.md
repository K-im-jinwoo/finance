# Project 1: 당일 단타 Stage 1 설계 초안

기준: 2026-11-13 KST. 상태: **OBSERVE_ONLY 오프라인 기반 구현; 합성 재생 검증, 실서버 웹소켓·실전진 모의운용 미검증**. 비용·점수·손절 정책과 Stage 2는 미확정이다.

사용자가 선택한 접근은 읽기 전용 실측 스파이크를 먼저 하고, 결과에 따라 당일 단타 전략과 모의 원장을 분리하는 1안이다. 본 문서의 수치 기본값은 모의실험 제안이며 수익성이 검증된 운용 규칙이 아니다. 기존 연구 전략의 승인된 기준을 바꾸지 않는다.

## 1. 범위와 보존 경계

- 국내 보통주, 현금 매수 후 당일 청산을 초기 대상으로 한다. 공매도·미수·레버리지·ETF/ETN·우선주·SPAC은 초기 대상에서 제외한다.
- `UNIFIED_RESEARCH_V1`, 기존 익일 시가 체결 엔진, `.runtime/hermes-paper.sqlite3`는 비교군으로 보존한다. 단타의 설정·신호·가상 거래는 이 원장에 쓰지 않는다.
- 신규 원장 기본 경로는 `.runtime/intraday-paper.sqlite3`, 초기 가상 자본은 10,000,000원이다. 기존 DB를 복제하거나 실계좌 자산을 읽어 초기화하지 않는다.
- 공유 인증, HTTP 오류 분류, KRX/DART 읽기 도구는 재사용한다. 전략 판정·세션 상태·모의 체결·원장은 별도로 둔다.
- 실제 주문, 계좌/보유/주문 이벤트 조회, Telegram 발송, WIKI 쓰기, 운영 DB 쓰기, 서비스 설치·재시작·스케줄 변경은 이번 범위에 없다. `orders_enabled=false`를 유지한다.
- 이번 읽기 전용 프로브는 **현재 유효한 공유 캐시 토큰만 읽는다**. OAuth 발급·401에 따른 캐시 무효화도 하지 않는다. TTL이 부족하면 중단한다. 이후 지속 수집의 갱신은 기존 공유 인증 소유자에게 맡긴다.

- `prices`는 최대 200종목을 받지만 응답은 종목·현재가·시각·통화이며 거래량·거래대금은 없다.

- 호가와 최근 체결은 REST로도 조회할 수 있다. REST 폴링은 중간 변화를 놓칠 수 있다. 차트·시세·랭킹은 서로 다른 호출 제한 그룹이다.
- 웹소켓은 계정당 동시 2연결, 연결당 채널×종목 합계 100구독, 구독 선언 초당 5회다. 세 번째 연결을 열면 가장 오래된 연결이 종료된다. 두 채널을 쓰는 5종목은 10구독, 10종목은 20구독이다. 최대치를 부하 시험으로 확인하지 않는다.
- 구독은 전체 교체 배열이며 ack의 수락·거부를 확인한다. 초기 스냅샷은 없으므로 REST로 초기 상태를 채운다. 정상 운영에서는 문서상 PING·재접속·재선언 규칙을 따른다.
- **체결·호가 스트림은 LOSSY이고 sequence가 없어 정확한 유실량을 알 수 없다.** 체결 프레임에 매수/매도 구분과 누적 거래량도 없다. 수신 틱 합산을 정확한 거래량·VWAP·체결강도로 사용하지 않는다.
- 국내 체결·호가는 KRX+NXT 통합 시세다. KRX 일봉과 통합 분봉의 거래량·세션·가격을 동일 기준이라고 가정하지 않는다. 초기 모의체결은 `INTEGRATED_KR_QUOTE_PAPER`라는 가정 모델이며 거래소별 체결 보장이 아니다.

### 2026-11-13 실제 REST 표본

관측 구간: **13:35:06~13:35:12 KST**. 기존 컨테이너에서 stdin으로 프로브를 실행했으며 원격 파일을 설치하지 않았다. 원장/DB를 열지 않고 공개 시세 GET만 요청했다.

| 현재가 2종목 | HTTP 200 | 277ms, 거래량 필드 없음 |

8건 성공·1건 429다. 관측 헤더 `X-RateLimit-Limit`는 랭킹 5, 시세 15, 차트 20이었다. 이는 **해당 응답의 그룹 한도 표본**이며 지속 처리량이나 제공자 내부 한도의 인증이 아니다. 마지막 429에도 `Remaining=19`, `Reset=1`이 표시됐고 `Retry-After`는 없었다. 응답 본문을 보존하지 않아 429의 세부 원인은 확인하지 못했다. 헤더 잔여량만 보고 요청 가능하다고 판단하지 않는다.

랭킹 `rankedAt`은 13:34:46.339 KST로 수신보다 약 20.6~21.4초 이전이었다. 요청 왕복 시간과 자료 자체의 나이를 구분한다. 짧은 단일 구간·2종목 표본이므로 장 시작/마감, 장시간 안정성, 목표 감시 종목 수를 검증한 결과가 아니다.

공유 토큰 캐시 바이트, 컨테이너 시작 시각·재시작 횟수가 전후 동일했다. 토큰 발급·무효화, 주문·DB·메시지 호출은 프로브에 없다. 독립적으로 움직이는 운영 DB 전체의 불변까지 입증한 것은 아니다.

실제 집계 근거: `.runtime/intraday-spike/rest-observation-20261113T043512Z.json`. 초기 원격 실행기 실패 기록은 별도로 보존하며 성공한 공급자 표본과 합치지 않는다.

### 웹소켓 관측 상태

**NOT_RUN_ACCOUNT_SLOT_UNKNOWN**. 사용자는 동일 계정의 다른 프로그램/PC 연결 사용 여부를 모른다고 답했다. 서버의 로컬 소켓 조사만으로 다른 PC의 계정 전체 연결 수를 확인할 수 없으므로 새 연결을 열지 않았다. 공식 한도는 확인했지만 실제 ack·지연·유실 징후·재접속은 미검증이다.

후속 실측은 빈 연결 슬롯을 확인한 뒤 1연결·2종목(4구독)부터 시작한다. 먼저 연결을 닫은 뒤 한 번 재연결하는 순서로 진행하고, 문서상 한도 초과나 기존 연결 강제 종료를 시험하지 않는다. 네트워크 지연과 서버/클라이언트 시계 차이가 섞이는 event age를 별도 표기한다.

## 3. 수집과 전략 경계

```text
기존 공유 인증 → 공개 REST 랭킹 / 초기 호가 / 완료 분봉
                             + 빈 슬롯 확인 후 WebSocket 체결·호가
                                      ↓
                         시각·통화·시장·유효성 검사
                                      ↓
                         단타 후보·신호 기록 (관측 모드)
                                      ↓
                         가상 거래 의도 → 보수적 모의체결
                                      ↓
                         단타 전용 원장·재생·평가
```

기존 재무 F 점수와 90일 뉴스/3년 위험 조사 완료를 단타 진입의 일괄 선행 조건으로 사용하지 않는다. 장전에는 거래정지·상장 상태·공식 중대 위험을 갱신하고 장중 새 공시/상태 변경을 반영한다. 오래된 위험 목록은 최신 확인으로 표시하지 않는다. 유상증자·CB가 존재한다는 이유만으로 중대 결격으로 단정하지 않고 제외 기준과 사건 근거를 명시한다.

위험 필터 통과 후 랭킹 합집합에서 감시 대상을 고른다. 집중 감시는 **최초 5종목, 최대 10종목은 실측 후 결정**한다. 15~30초 고정 주기를 확정하지 않는다. 랭킹 자료 나이, 변경 빈도, HTTP 결과, 그룹별 예산과 기존 소비자의 호출을 함께 반영한다. 429에는 신규 호출을 멈추고 냉각 상태로 전환하며 자동 폭주 재시도는 없다.

수집 어댑터는 `market`, `symbol`, `source`, `source_timestamp`, `received_at_utc`, `received_monotonic`, `session_id`, `quality`, `schema_version`을 제공한다. 전략은 통신 방식에 직접 의존하지 않는다. 원본 공개 자료와 계산 입력을 추적할 수 있도록 별도 관측 파일의 해시·시각을 기록하며 비밀정보·계좌정보는 넣지 않는다.

연결 단절·오래된 호가·필수 자료 누락·불일치 시 신규 진입은 막는다. 연결 복구만으로 즉시 재개하지 않고 REST 스냅샷과 완료 분봉을 다시 확보해 준비 상태를 회복한다. 중복처럼 보이는 동일 틱을 sequence 없이 같은 거래로 단정하지 않는다.

## 4. 점수 입력과 계산 가능 범위

| 제안 입력 | Stage 1 처리 |
| --- | --- |
| 1분봉 추세·상대 거래량·변동성 | 공식 완료 분봉에서 결정론적으로 계산. 현재 봉은 비교 기준 평균에서 제외 |
| VWAP | 실제 체결 전체와 거래대금/거래량 계약 확보 전 정확한 당일 VWAP은 제공하지 않음. 필요 시 `BAR_TYPICAL_VWAP_APPROX = Σ((H+L+C)/3×V)/ΣV`라는 분봉 근사값으로 별도 표시 |
| 체결강도 | 매수/매도 체결 수량이 없어 전통적 체결강도는 `UNAVAILABLE`. 틱 방향 추정치를 같은 이름으로 대체하지 않음 |
| 호가 불균형 | 같은 시각의 유효한 호가에서 계산. 취소 가능한 잔량이므로 단독 진입 근거로 사용하지 않음 |
| 일봉 | 장전까지 완료·확보된 자료만 사용. 당일 미래 종가를 사용하지 않음 |

진입 점수와 청산 점수는 별도로 계산하되 가중치·임계값은 **웹소켓/분봉 품질 실측 후 단일 기준 전략으로 고정**한다. 이 초안은 구체적인 점수표가 확정된 상태가 아니며, 현재 매매 가능 판정을 생성하지 않는다. 없는 지표를 0점·중립값으로 채우거나 자동 재배점하지 않는다. 체결강도 없이 시작하는 기준 모델이라면 그 입력 목록과 정책 버전을 명시한다.

현재 구현의 모드는 `OBSERVE_ONLY`이며 `PAPER_READY` 전환 경로는 없다. 실제 관측 데이터에서는 실행 의도와 체결을 거부한다. 명시적인 `SYNTHETIC` 데이터셋과 fixture 비용 가정으로 생성한 별도 원장에서만 합성 체결을 검산한다. 신호 시각 이후의 최신 관측 호가로만 가상 체결할 수 있다. 봉 종가로 만든 신호를 같은 봉의 과거 저가나 종가에 소급 체결하지 않는다.

## 5. 모의 원장과 비용·체결

현재 단타 SQLite 테이블은 `meta`, `state`, `events`, `observations`, `paper_fills`다. 세션·포지션·의도·청산 요청·직교 위험 잠금은 `state`의 canonical JSON에 함께 저장한다. 신호는 점수 미확정 상태로 사건 원장에 기록한다. 모든 판정·신호·체결에는 정책 버전과 입력 해시를 연결하고 원본 이력을 수정해 성과를 덮어쓰지 않는다. 재실행 시 동일 사건 키로 중복 체결을 막고, 현금·수량·비용과 사건 기록은 하나의 SQLite 트랜잭션으로 처리한다.

- 가상 매수는 신호 시각+설정 지연 이후 관측한 매도 호가, 가상 매도는 매수 호가를 기준으로 한다. 당시 관측 자료가 없으면 소급 체결하지 않는다.
- 호가별 가용 잔량과 보수적 참여율을 고려해 부분 체결·미체결을 허용한다. 호가 잔량만으로 실제 체결 순서를 입증할 수 없다.
- 호가 기준 가격에는 이미 스프레드가 반영된다. 여기에 스프레드를 다시 비용으로 더하지 않는다. 추가 슬리피지·충격 가정은 별도 항목으로 둔다.
- 수수료는 매수·매도, 증권거래세/농특세는 해당 매도에 적용한다. 적용일·시장·세목·반올림·출처를 가진 `cost_schedule`을 고정한다. 실제 계좌 우대율을 추정하지 않으며 비용 미확정 시 `PAPER_READY`를 부여하지 않는다.
- 계산은 Decimal/원화·정수 수량으로 한다. 손익은 명시된 비용과 매수·매도 현금흐름에서 독립적으로 대조한다.
- 웹소켓 유실 가능성·시장 통합·대기 순서 부재 때문에 모의 수익을 실제 체결 가능한 수익이라고 보고하지 않는다.

## 6. 시간·손실 제한 기본값

아래 숫자는 사용자 제안을 채택한 **모의실험 기본값**이다. 공식 거래일/세션 확인을 먼저 적용한다. 초기에는 정상 KRX 정규장 시간표인 날만 지원하며 지연 개장·조기 종료 등 특수 일정은 진입을 막고 별도 검증한다. 고정 시각을 모든 거래일에 일반화하지 않는다.

| 항목 | 제안 규칙 |
| --- | --- |
| 신규 진입 종료 | 14:50 KST 이상 신규 진입과 신규 매수 의도 생성 금지 |
| 시간 청산 | 15:15 KST부터 잔여 가상 포지션의 청산 시도. 점수보다 우선 |
| 종목별 비중 | 신규 진입/추가 편입 시 비용 포함 평가자산의 최대 20%; 가격 변화에 따른 자동 리밸런싱은 없음 |
| 동시 보유 | 최대 3종목, 신규 진입 시 합계 최대 60%, 현금 범위 안에서만 편입 |
| 일일 손실 | 당일 시작 평가자산 대비 비용 차감 실현+미실현 손실률이 -3% 이하이면 신규 진입을 차단하고 기존 포지션 청산 절차 진입 |
| 중단 후 | 같은 날 자동 재개 없음. 청산 시도와 관측은 계속하며 매도까지 중단하지 않음 |

미실현 손익은 유효한 매수 호가와 예상 청산 비용으로 보수적으로 평가한다. 호가가 오래되면 평가 불확실성을 표시하고 진입을 막는다. 가격 급변으로 -3%보다 손실이 커질 수 있으므로 이 값은 보장된 최대 손실이 아니다.

**오버나잇 금지는 목표와 통제 규칙이다. 강제 청산 성공을 보장하지 않는다.** 거래정지·데이터 단절·호가 부재로 청산할 수 없으면 `UNFLATTENED`와 원인을 기록한다. 현금을 돌려주거나 가짜 체결로 포지션을 지우지 않는다. 해당 일자는 운영 합격 실패로 처리하고, 포지션 해결 전 다음 날 신규 진입도 막는다. 종목별 손절·이익 실현·최대 보유 시간은 기준 전략을 고정할 때 별도로 결정한다.

## 7. Stage 1 평가와 다음 단계 검토

최소 20거래일·30회 완결 라운드트립·비용 차감 누적 순수익 > 0은 **운영 관측을 위한 최소 표본**으로만 채택한다. 거래 수를 채우려고 신호를 만들거나 신호가 없는 날을 제외하지 않는다. 30회로 통계적 우위를 확정하거나 실제 주문을 활성화하지 않는다.

다음 단계 검토에는 아래 결과가 함께 있어야 한다.

1. 고정된 정책 버전과 거래한 모든 날·기각 신호·미체결·잔여 포지션을 포함한 원장.
2. 진입 차단/시간 청산 시도/손실 한도 발동 규칙의 모든 위반 0건. 실제 청산 실패는 별도 실패로 포함.
3. 최대 낙폭, 최악의 거래/하루, 종목·일별 수익 집중도, 부분 체결·미체결 비율.
4. 기본 비용과 지연/추가 슬리피지를 높인 보수적 가정의 민감도 결과. 손익 부호가 바뀌는지 공개.
5. 규칙을 바꿨다면 기존 검증 기간에 맞춰 성과를 합치지 않고 정책별로 분리. 정책 고정 후 별도 전진 관측 구간 확보.
6. 데이터 품질 장애·재시작·중복 재생·장 마감 예외에 대한 오프라인 검증과 실제 관측 경계.

Stage 2의 자금·주문 범위는 아직 정의하지 않았다. 위 조건을 만족해도 자동 승격이나 실주문 연결은 없다. 후속 단계 검토와 범위 결정은 별도다.

## 8. 의존성과 검증 계획

Python 표준 라이브러리로 RFC 6455 클라이언트를 새로 구현하지 않는다. JSON 구독 프로토콜·상태 머신·가짜 서버/소켓 하니스는 표준 라이브러리만 사용한다. 선택 런타임 전송 계층은 `engine/pyproject.toml`의 `daytrade = ["websockets>=15,<18"]` extra와 lazy import로 분리했다. 이 버전 범위의 실연결 호환성은 아직 검증하지 않았다. 기본 엔진/대시보드의 `dependencies=[]`는 유지하며 이번 오프라인 구현에서 라이브러리를 설치하지 않았다.

기존 호스트 Hermes Python에는 `websockets`가 존재함만 확인했다. 해당 라이브러리로 실제 handshake를 성공했다고 보고하지 않는다. 프로브의 웹소켓 경로는 슬롯 확인 플래그 없이는 실행하지 않으며, 현재 실측 결과에는 포함하지 않는다.

오프라인 테스트는 fixture/mock만 사용한다. 인증 캐시 재발급 금지·없는 캐시 생성 금지·읽기 경로 제한·요청 예산·429 중단·리다이렉트 차단·비밀정보 출력 금지·웹소켓 슬롯 미확인 시 연결 금지를 확인한다. 이후 모듈 구현에서는 정상 입력뿐 아니라 시각 역전, 진행 봉, 누락 자료, 세션 변경, 중복 재생, 부분 체결, 청산 불가, 손실 한도 경계를 검증한다.

현재 미확정: 웹소켓 빈 슬롯과 실제 수신 품질, 장시간/개장/마감 관측, 정확한 비용 일정, 지연·체결 가정, 단일 전략 점수·임계값, 종목별 손절·보유 시간, 이후 Stage 2의 의미와 범위.

## 9. agy 지시 반영: 오프라인 구현 경계

2026-11-13 추가 구현 지시를 반영했다. 기존 `stock_assistant/intraday.py`와 충돌하지 않도록 **`stock_assistant/daytrade/`**를 사용한다. 기존 엔진의 `build_intraday_signal`, `quote_freshness`, CLI와 원장은 변경하지 않는다.

- 프로브는 비-200에서 `ApiError.code`와 헤더 `X-Request-Id`만 추가 추출한다. 메시지·data·본문 requestId·인증 정보는 출력하지 않는다. 프로브 재시도는 0회다.
- 런타임 REST는 내부 `RANKINGS`(제공자 명칭 `RANKING`), `MARKET_DATA`, `MARKET_DATA_CHART`를 분리한다. 429에는 잔여 한도와 무관하게 냉각하며 지수 백오프와 주입된 PRNG jitter를 사용한다. 연속 429 기준 기본 3회는 통신 장애 제어 값이다. `RATE_LIMIT_DEGRADED`는 성공 응답 하나로 지우지 않고 그룹별 명시적 복구를 요구한다. 신규 진입은 막되 `EXIT_MONITOR`는 냉각을 준수하며 조회할 수 있다.
- 시세 신선도 한도는 미확정 매매 정책이므로 실제 기본값을 만들지 않았다. `QualityPolicy`의 한도가 없으면 진입 불가다. 테스트의 한도·비용·지연·참여율은 전부 합성 입력이다.
- 시간 단계 `OPEN → ENTRY_CLOSED → TIME_EXITING → CLOSED`와 `LOSS_LOCKED`, `RATE_LIMIT_DEGRADED`, `DATA_DEGRADED`, `PRIOR_DAY_UNFLATTENED`의 이유 집합을 독립 저장한다. 시간 전환은 잠금을 지우지 않는다. 일일 손실 잠금만 새 세션 날짜에서 초기화되며 미청산·자료·호출 잠금은 유지한다.
- 15:15 또는 손실 발동 시 청산 요청을 기록한다. 유효한 최신 호가가 없으면 현금·수량을 바꾸지 않는다. 15:30 이후 잔여 포지션은 `CLOCK`만으로도 `UNFLATTENED`로 기록한다. 다음 날짜에도 보유가 남으면 신규 진입을 막는다.
- 현금 항등식/수량 검산은 저장된 체결 현금흐름에서 독립 계산한다. 평가자산은 유효한 매수 호가·가정 청산 비용/추가 슬리피지로 계산한다. 시세가 없으면 `MARK_UNCERTAIN`, 자산 숫자는 `None`이고 현금 검산 결과와 구분한다.
- 재생은 시간·명시 sequence·불변 정책 버전·원장에 고정한 seed를 사용한다. 동일 ID/내용은 무시하고 다른 내용이면 거부한다. 중복 재생은 원장 해시와 DB 바이트를 유지한다. 입력 파일 순서의 해시와 의미상 원장 해시는 별도다.
- 모의 원장은 지정 루트의 `.runtime/intraday-paper.sqlite3`만 허용한다. 기존 파일 초기화·덮어쓰기, symlink/redirect/hardlink 경로와 다른 SQLite 종류를 거부한다. CLI는 기존 원장 대신 매번 명시적인 새 루트를 요구하며 재생 API는 검증된 원장을 재개할 수 있다.

구현 및 합성 실행 방법은 `engine/src/stock_assistant/daytrade/README.md`를 따른다. 실서버 연결이나 추가 REST 실측은 이 구현의 검증에 포함하지 않는다.
