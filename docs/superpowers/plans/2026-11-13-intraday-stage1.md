# Project 1: 당일 단타 Stage 1 구현 계획

기준: 2026-11-13 KST. 설계: [검토용 초안](../specs/2026-11-13-intraday-stage1.md).

상태는 코드·실행 근거에 따라 갱신한다. 모의 엔진 전체 구현이나 운영 적용 완료를 뜻하지 않는다. 기존 미커밋 작업과 원장을 보존한다. 작업 브랜치는 `codex/intraday-stage1-spike`이며 커밋/푸시/배포는 수행하지 않는다.

## Task 1. 최소 읽기 전용 프로브

완료 범위:

- `scripts/toss_intraday_probe.py`: 유효한 기존 SharedTokenCache 토큰 읽기, 허용된 공개 GET 5경로, 최대 10요청, 요청 사이 0.5초 간격, 429/401/예외 시 중단, 자동 재발급·무효화·재시도 없음.
- `tests/test_toss_intraday_probe.py`: 외부 호출 없이 인증 경계·누락/만료 캐시·리다이렉트·429·요청 예산·비밀정보 출력·웹소켓 슬롯 가드 검사.
- REST 1.2.28 / AsyncAPI 1.2.3 원문과 해시를 `.runtime/intraday-spike`에 보존.
- 실제 Oracle REST 관측: 8 HTTP 200, 1 HTTP 429 후 중단. 공유 캐시 바이트와 컨테이너 시작/재시작 메타데이터 유지 확인. 자세한 결과는 설계 문서 참조.

원격 실행은 기존 컨테이너의 비루트 Python에 stdin으로 전달했다. 실행기에 원문을 붙일 때 `from __future__` 앞에 코드를 추가하지 않고 `python -B -c` 로더에서 stdin을 독립적으로 compile한다. 원격 파일 복사/서비스 설치는 필요 없다. 기존 공유 인증 코드 경로만 `sys.path`에 추가한다. 서버/키 경로는 실행 환경에서 지정하며 새 코드에 서버 주소를 하드코딩하지 않는다.

현재 프로브 실행 인자:

```text
python -B scripts/toss_intraday_probe.py --client-id-file <기존 Client ID 파일> --cache-dir <기존 공유 캐시>
```

코드가 있는 로컬/서버 Python에서 canonical engine과 `shared_toss_auth`를 import할 수 있어야 한다. 캐시는 기존 private 디렉터리와 lock/token 파일을 요구한다. Client Secret을 새로 읽거나 전달할 필요는 없다. stdout에는 공개 응답 구조와 시각·헤더 집계만 남긴다. 결과 JSON은 로컬 `.runtime`에 보존하고 Git에 넣지 않는다.

미완료:

- 계정 전체 웹소켓 빈 슬롯 확인. 사용자는 현재 사용 여부를 모른다고 답했으므로 플래그를 주지 않는다.
- 실제 웹소켓 수신·ack·재접속과 5~10종목 부하 관측. 공식 한도와 실측을 구분한다.
- 차트 429의 원인과 안전한 재시도 간격. 기존 표본을 근거로 즉시 반복 조회하지 않는다. 후속 승인된 실측에서 공개 오류 코드만 안전하게 기록하고, 정상 부하·제공자 정책을 확인한다.

## Task 2. 시세 어댑터와 관측 모드

구현 경로: `engine/src/stock_assistant/daytrade/`의 데이터 계약·REST/웹소켓 어댑터와 별도 CLI. 기존 `intraday.py`와 이름 충돌을 피하며 `providers/toss.py`의 공개 인터페이스는 유지한다.

1. 필수 필드·시각·통화·세션·품질 상태를 고정한다. 모든 입력은 게시/수신 시각으로 미래정보를 거부한다.
2. REST 랭킹 합집합/중복 제거, 위험 목록 갱신, 5종목 집중 감시를 구현한다. 전체 시장 거래량과 토스 고객 거래량을 혼합하지 않는다.
3. 웹소켓 선택 의존성 버전·기존 설치 환경·인증 연결 방식을 확정하고 오프라인 가짜 서버로 ack·일부 거절·단절·PING·재선언을 검증한다. 기존 연결을 닫고 재연결하며 중첩 연결을 만들지 않는다.
4. 완료 분봉·일봉에서 입력을 계산한다. 틱 합산 VWAP/체결강도는 구현하지 않는다. 분봉 근사 지표라면 이름·공식을 명시한다.
5. 시세 원본/입력 해시/신호를 관측 모드로만 기록하고 데이터 품질 보고서를 만든다. KRX+NXT 통합값과 KRX 일봉 비교의 차이를 표시한다.

완료 기준: 동일 관측 자료의 재생 결과 일치, 지연·누락·연결 장애 시 진입 불가, 실제 수집 범위/기간 공개. 가격 신호가 매수 권유나 체결로 자동 승격되지 않는다.

## Task 3. 단일 전략 고정과 모의 원장

1. 실측 결과를 보고 가용 지표만으로 매수·매도 점수표, 가중치, 임계값, 종목별 손절·최대 보유 시간, 비용 일정을 하나의 정책 파일로 고정한다. 검토용 설계에 추측으로 확정하지 않는다.
2. `.runtime/intraday-paper.sqlite3`를 별도 생성하는 opt-in CLI를 구현한다. 기존 원장과 경로가 같거나 기존 파일이면 초기화를 거부한다. 실계좌/기존 DB에서 자산을 복사하지 않는다.
3. 신호 이후 관측 호가, 지연, 잔량, 참여율, 수수료·세금·추가 슬리피지를 적용한다. 스프레드를 이중 계산하지 않는다.
4. 14:50 진입 종료, 15:15 청산 시도, 20%/3종목, 일일 -3% 손실 발동을 구현한다. 발동 이후 신규 매수는 막고 청산은 계속한다.
5. 청산 불가는 실제 실패 상태로 남긴다. 장 마감에 임의 가격으로 가상 체결하거나 잔여 포지션을 삭제하지 않는다.

완료 기준: 원화·수량·비용·현금 독립 검산, 정상/경계/예외·재시작·중복 재생 회귀 검증, 기존 연구/원장 불변 검사. 이후 실제 실행은 별도 원장의 명시적 모의 모드로만 한다.

## Task 4. 전진 관측과 평가 보고서

1. 모든 거래일·기각 신호·부분 체결·미체결·실패를 포함해 최소 20거래일과 30회 완결 거래를 관측한다. 횟수 조건을 맞추기 위해 거래를 생성하지 않는다.
2. 순수익뿐 아니라 낙폭·최악일·수익 집중도·규칙 위반·데이터 품질·청산 실패·보수적 비용 민감도를 보고한다.
3. 정책 변경 시 구간을 분리하고 고정 정책으로 다음 관측 구간을 확보한다. 동일 표본에 맞춘 튜닝 결과를 검증 성과로 합치지 않는다.
4. 다음 단계 검토 자료를 만들되 실주문을 활성화하지 않는다. Stage 2의 범위는 별도로 정한다.
