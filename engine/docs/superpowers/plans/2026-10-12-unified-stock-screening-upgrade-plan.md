# 재무와 뉴스 통합 평가 및 매수 추천 고도화 계획

기준일: 2026-10-12 KST. 상태: 진단과 재무 평가 기반 로컬 구현, 운영 미적용.

목표는 재무로 검토 가능한 기업을 먼저 좁히고, 그 기업들의 과거 위험과 현재 뉴스·공시를 평가해 하나의 순위를 만드는 것이다. 최종 보고서는 매수 추천, 관찰, 검증 미완료, 제외를 구분한다. 거래량의 일시적인 변화보다 추천과 위험의 의미 있는 변화를 알려준다.

이번 대화에서 확인한 방향은 재무 우선 스크리닝, 변경된 재무만 재평가, 통과 기업의 뉴스 검토, 과거 악재 확인, 항목별 점수와 총점 공개, 실제 매수 추천으로 이어지는 판정이다. 아래 가중치·배점·임계값·조사 기간·알림 변경은 비교 검증을 위한 제안이며 운영 정책으로 확정하지 않는다. 이 계획의 작성은 구현·운영 배포·모의계좌 정책 변경 승인을 뜻하지 않는다.

## 현재 동작과 개선 대상

| 확인한 현재 동작 | 개선할 동작 |
| --- | --- |
| 가격·거래량·재무·공시를 섞은 기본 후보 최대 5개와 뉴스 후보 최대 5개를 별도로 표시 | 재무를 통과한 기업 안에서 사건 평가를 거쳐 단일 후보 목록 생성 |
| 뉴스 후보는 제외 대상이 아니면 `추가 검토 / 매수 보류`를 고정 표시 | 실제 최종 판정과 구체적인 미충족 조건 표시 |
| 경고나 추가 확인 항목이 하나라도 있으면 기본 후보를 보류 | 결격, 필수 검증 미완료, 점수 감점, 가격 대기를 구분 |
| 재무 적재 대상 선정에 기존 가격 중심 순위가 사용됨 | 전체 대상의 기초 재무 확보와 재무 기반 통과 목록을 먼저 구성 |
| 재무 갱신 필요성을 사업연도·TTM 나이 등으로 판단 | 보고서 접수번호와 정정·신규 공시를 확인해 변경 기업만 재평가 |
| 최근 48시간의 제한된 검색어와 제목·요약 중심 뉴스 발견 | 기업별 과거 사건과 후속 정정·해결 상태를 유지하고 신규 재료를 추가 |
| 최근 1분봉 거래량 3배 이상, 동일 종목 30분 재알림 제한 | 단순 거래량 경고의 Telegram 전송 중단을 기본 제안으로 검토하고 의미 있는 판정 변화 중심으로 알림 |

로컬 재현에서는 같은 양호한 입력도 공시 조사 범위가 미확인이면 95점에 매수 보류가 나왔다. FCF 음수 경고를 추가하면 90점에 매수 보류가 나왔다. 이는 현재 규칙의 동작 증거이며 실제 최근 운영 종목들의 보류 원인 집계는 아니다.

## 평가 흐름과 대상

```text
전체 대상 종목
  → 기초 재무 확보와 기업 유형 분류
  → 재무 필수조건 판정 및 재무 점수
  → 통과 기업의 과거 위험과 최신 뉴스·공시 조사
  → 사건 단위 재료 점수와 위험 판정
  → 총점 계산 및 단일 순위
  → 가격과 진입 조건 확인
  → 매수 추천 / 관찰 / 검증 미완료 / 제외
```

초기 통합 점수는 일반기업 보통주에 적용한다. 금융회사와 ETF는 기존 별도 기준을 유지하고, 일반기업과 같은 점수로 비교하지 않는다. 금융회사·ETF 평가 확대는 별도 후속 범위다. 기존 제외 대상인 우선주·SPAC·KONEX·ETN·레버리지·인버스 ETF는 유지한다.

재무 통과 목록은 최종 5개보다 넓게 유지한다. 아직 뉴스 검토를 끝내지 못한 기업은 검토 대기 목록에 남긴다. 뉴스 조회 예산 때문에 조사하지 못한 기업을 낮은 평가의 기업으로 취급하지 않는다. 순위는 검토 완료 대상 안에서 생성하고 전체 대상 수, 재무 검토 완료 수, 통과 수, 뉴스·위험 검토 완료 수를 함께 표시한다.

기존 보유종목은 신규 후보 목록에서 빠져도 위험 점검을 계속한다. 순위 하락은 자동 청산 근거가 아니다.

## 재무 평가와 갱신

### 필수조건

최신 연간·최근 12개월 영업이익과 일반기업 영업현금흐름 양수라는 기존 필수조건을 보존한다. 연간·누적·전년 동기 수치의 연결 또는 별도 기준, 통화, 기간을 일치시킨다. TTM은 구성 보고서와 계산식을 남긴다. OCF는 기존 연간 기준을 유지하며 TTM OCF로 바꾸려면 별도로 비교하고 확정한다.

필수 수치가 기준에 미달하면 제외한다. 누락·오래됨·기업 유형 미확인·기간 불일치는 검증 미완료다. FCF 음수와 CB·BW·유상증자 존재만으로 일괄 제외하지 않는다.

### 재무 점수 제안

| 평가 항목 | 초기 배점안 | 확인할 내용 |
| --- | ---: | --- |
| 이익 지속성 | 25 | 연간·TTM 흑자, 여러 기간의 흑자 유지와 변동성 |
| 영업현금흐름의 질 | 25 | 양수 지속, 이익과 현금 창출의 일관성 |
| 이익 개선 추세 | 20 | 비교 가능한 전년 동기·최근 기간의 개선 또는 악화 |
| 매출채권·재고자산 회전율 | 15 | 기존 선호 기준인 유지·상승과 악화 원인 |
| FCF와 투자 지출 | 15 | 현금 창출, 성장 투자와 구조적 현금 부족 구분 |
| 합계 | 100 | 필수조건 통과 후 비교 점수 |

세부 구간·산식은 실제 확보 가능한 계정과 사례 비교 후 고정한다. 금액의 절대 크기로 대기업에 자동 가점을 주지 않는다. 업종이 다른 기업의 비율을 무조건 같은 구간으로 평가하지 않는다.

선택 지표가 누락되면 원값은 null로 남기고 해당 가점을 부여하지 않으며 다른 항목의 배점을 올려 보정하지 않는다. 이것만으로 자동 보류하지 않는다. 점수 산출에 필수인 핵심 자료가 없거나 이미 확인된 악화의 원인 검증이 필요한 경우는 별도 차단 사유로 기록한다.

초기 자료 확보안은 최근 3개 결산연도와 최신 TTM 계산에 필요한 분기·반기 및 전년 동기 자료다. 모든 대상의 기본 재무를 확보하는 대기열을 만들고, 가격 상위 30개만 조사하는 순환 구조를 끊는다. 기존 API의 다중 회사·재무 다운로드 활용 가능성과 계정 일관성을 먼저 확인한다.

### 변경 기반 갱신

공시 목록의 새 접수번호와 정정 여부를 기존 작업 시간대에서 확인한다. 새 재무 보고서·정정 보고서·분류 변경·필수 자료의 유효기간 만료가 있으면 해당 기업만 재계산한다. 변경이 없으면 같은 스냅샷과 점수를 재사용한다. 새 스케줄이나 호출량 증가는 이 계획에서 자동으로 확정하지 않는다.

현재의 `already_current` 판정은 정정 접수번호까지 확인하는 구조가 아니므로, 기간과 나이만으로 갱신을 생략하는 로직을 보완한다. 원보고서와 정정본을 연결하고 이전 시점에 유효했던 수치를 덮어쓰지 않는다.

## 과거 위험과 뉴스 평가

### 최초 조사와 후속 갱신

기업이 처음 재무 통과 목록에 들어오면 과거 공시를 중심으로 위험 이력을 조사하고 뉴스를 보완 근거로 연결한다. 기존 조사 창인 희석성 조달 5년과 경영진 위험 10년을 보존한다. 일반 뉴스의 최초 조사 창은 최근 3년을 비교안으로 두며, 더 오래된 미해결 사건은 조사 창 밖이어도 현재 위험으로 추적한다.

이후에는 신규 사건·정정·취소·판결·해결과 현재 유효성만 갱신한다. 필수조건 미달 기업에 대한 신규 투자용 뉴스 조사는 생략하되 기존 보유와 미해결 위험 사건의 점검은 계속한다.

뉴스 검색에는 결과·페이지 제한이 있으므로 검색 결과가 없다는 이유로 과거 위험이 없다고 확정하지 않는다. 조사한 공급자, 검색어, 기간, 페이지, 누락·실패와 마지막 확인시각을 기록한다. DART 목록 수집 완료도 사건 내용과 현재 상태의 검증 완료를 뜻하지 않는다. 본문과 필요한 후속 근거가 확보되어야 평가 상태를 승격한다.

### 기사 대신 사건 평가

한 사건에 여러 기사를 연결한다. 사건은 종목·유형·공시 접수번호 또는 확인된 계약 등 사업상 식별자로 묶는다. URL·제목 중복 제거 외에 재배포와 후속 보도를 연결하고, 동일 사건 여부가 불확실하면 가점을 중복 부여하지 않는다.

사건마다 유형, 핵심 사실, 금액과 사업 영향, 원문 근거, 공식 확인 여부, 발표·공급자 제공·관측·최초 확보 시각, 유효기간, 정정 관계, 현재 상태를 남긴다. 회사명 변경과 별칭은 검증된 법인코드·종목코드에 연결하고 모호한 회사 매칭은 검증 대기로 둔다.

AI를 사용하는 경우 사건 후보와 근거 위치를 구조화하는 보조 역할에 한정한다. AI의 판단만으로 사실 확인·결격·점수를 확정하지 않는다. 점수와 판정은 검증된 입력과 버전이 고정된 규칙으로 계산한다. 재현에 필요한 추출 결과와 검증 상태를 보존한다.

### 현재 재료 점수와 위험 감점

| 사건 | 평가 방식 |
| --- | --- |
| 수주·공급계약 | 공식 확인, 금액의 연매출 대비 비중, 기간·조건·이행 상태 평가 |
| 실적 개선 | 재무에 이미 반영된 동일 실적의 중복 가점 차단, 새 정보의 영향만 평가 |
| 허가·승인 | 확정 여부와 실제 사업 관련성 평가 |
| 정책 수혜 | 직접 선정·공식 근거와 회사의 실제 노출 확인 |
| 루머·기대·목표주가·단순 홍보 | 긍정 재료 가점 없음 |
| 취소·해지·정정 | 이전 가점을 회수하고 남은 사업 영향에 따라 위험 평가 |
| 희석성 조달 | 규모·목적·반복성·리픽싱·현재 잔여 물량을 위험 항목에서 평가 |
| 횡령·배임·회계·지배구조 위험 | 공식 사실과 의혹, 미해결과 해소 상태를 구분해 제외 또는 검증 보류 |

현재 재료 점수 N은 0~100이며, 조사 완료 후 긍정 재료가 없는 경우의 기준점은 50으로 제안한다. 긍정 사건의 검증 수준·사업 영향·현재 유효성에 따라 가산하고 100을 넘지 않는다. 미조회·실패·조사 불완전에는 기준점 50을 부여하지 않고 null로 둔다. 세부 가산 구간과 시간 경과에 따른 감소는 사례 비교 후 고정한다.

비결격 위험은 R로 한 번만 감점한다. 초기 비교안은 사건 영향에 따른 5·10·20점 구간과 총 감점 상한 30점이다. 과거 뉴스의 반복 보도만으로 감점을 누적하지 않는다. 미해결 중대한 위험은 기간 경과로 소멸시키지 않는다. 공식적인 해소는 새로운 증거에 따라 반영한다. 중대한 결격은 감점 상한과 관계없이 제외하며 확인이 필요한 중대한 의혹은 검증 미완료다.

FCF·이익 악화와 같은 재무 평가 항목은 재무 점수에서 처리하고 같은 사실을 R에서 다시 감점하지 않는다. 취소 사건은 효력을 잃은 호재 점수를 회수하되, 위험 감점은 별도로 입증된 잔여 영향에만 부여한다.

### 호출 예산

기존 프로그램 한도 일 20회·월 500회, 1시간 재조회 제한, 요청 전 예약과 실패 시 예약 유지, 유료·정책 불명확 시 차단을 보존한다. 공급자 문서의 일반 한도를 프로그램의 승인 한도로 사용하지 않는다.

최근 사건 점검에 필요한 예산을 먼저 배정하고 남은 예산으로 최초 조사를 순환한다. 변경 발생 기업, 기존 보유, 최종 추천 후보, 오래 미검토한 통과 기업을 우선하되 마지막 검토시각을 반영해 일부 기업이 계속 누락되지 않게 한다. 월 잔여 예산과 남은 실행 기회를 함께 계산하며 일 20회 사용을 매일 보장하지 않는다. 예산 부족은 검증 대기 사유로 표시하고 유료 또는 별도 크롤러로 우회하지 않는다.

## 총점과 최종 매수 판정

총점의 초기 비교안은 다음과 같다.

```text
S = max(0, min(100, 0.70 × F + 0.30 × N − R))
F = 재무 점수 0~100
N = 조사 완료된 현재 재료 점수 0~100
R = 검증된 비결격 위험 감점 0~30
```

필수조건 실패와 중대한 결격은 총점 계산보다 먼저 적용한다. 필수 조사나 핵심 점수가 미완료이면 S는 확정하지 않는다. 점수는 수익 확률이 아니며 서로 다른 규칙 버전의 숫자를 직접 비교하지 않는다.

| 최종 판정 | 조건과 표현 |
| --- | --- |
| 매수 추천 | 재무 필수조건 통과, 필수 위험·뉴스 조사 완료, 결격 없음, F와 S 기준 충족, 유효한 진입 조건 있음 |
| 관찰 | 검토는 완료됐으나 점수 또는 가격·진입 조건 미충족. 부족한 항목 명시 |
| 검증 미완료 | 핵심 자료·공식 근거·필수 조사 범위 미확인. 보완할 작업과 실패 원인 명시 |
| 제외 | 기존 필수조건 미달 또는 확인된 중대한 결격. 근거와 재검토 조건 명시 |

비교용 출발값은 F 70점 이상, S 75점 이상이다. 70:30과 이 두 임계값은 운영 확정값이 아니다. 80:20 및 60:40을 제한된 비교안으로 두고 사전에 선정한 사례와 시간 분리 평가로 확인한다. 추천 개수를 맞추기 위해 기준을 낮추지 않는다. 조건 충족 종목이 없으면 `오늘 매수 추천 없음`을 표시한다.

판정 우선순위는 결격 확인, 핵심 검증 누락, 점수 충족 여부, 가격·진입 조건 순서다. 일반 경고는 별도로 보여주고 모든 경고를 하나의 보류 조건으로 묶지 않는다. 조사가 끝난 경고는 근거와 처리 결과를 연결해 종료한다. 조회 실패는 기업의 악재로 분류하지 않는다.

### 장중과 장외의 진입 조건

첫 비교에서는 기존 바닥 반등·상승 지속·유동성 조건을 재사용한다. 진입 허용 범위·유효기간·추격 제한·무효화 계산은 규칙으로 명시하고 사례 검증 후 고정한다. 단순 점수 상승이나 AI 해석만으로 가격 조건을 통과시키지 않는다.

장중에는 신선한 시세로 현재 충족 여부를 확인한다. 오전·장외에는 최신 완료 거래일 자료로 다음 거래 세션의 조건을 계산하고 `매수 추천 다음 장 조건부`로 표시할 수 있게 한다. 실제 다음 장 가격을 본 것처럼 쓰지 않는다. 조건을 계산할 필수 자료가 없으면 검증 미완료, 실제 관측 가격이 허용 범위를 벗어나면 관찰이다. 장외라는 이유만으로 모든 추천을 보류하지 않는다.

진입 상태는 현재 충족, 다음 장 조건부, 가격 대기, 확인 불가로 나누고 근거 가격·거래일·관측시각·조건 유효기간을 표시한다. 이후 장중 평가에는 별도 평가 ID와 시각을 부여해 저장된 보고서·점수·순위를 소급 수정하지 않는다. 추천은 실제 주문을 생성하지 않는다.

| --- | --- | --- |

| S 80이지만 가격 조건 미충족 | 기업 순위 유지 | 관찰과 구체적인 가격 조건 표시 |

## 보고서와 Telegram 알림

최종 추천은 총점 기준 최대 5개이며 한 종목은 한 번만 나타난다. 정렬은 S 내림차순, F 내림차순, 종목코드 순으로 재현 가능하게 한다. 관찰과 검증 대기는 추천 목록과 구분하고 개수와 핵심 변경만 요약한다. 시장 전체 조사 완료를 확인하기 전에는 검토 완료 대상의 순위라고 표시한다.

각 종목에는 재무·재료 점수, 위험 감점, 총점, 최종 판정, 핵심 근거, 진입 조건, 무효화 조건, 실제 자료 기준일, 미확인 항목을 표시한다. 점수가 바뀌면 기사의 개수가 아니라 새 사건·공시 정정·조건 변경 중 무엇이 원인인지 보여준다.

단순 장중 거래량 경고의 Telegram 전송은 끄는 방향을 제안한다. 데이터 조회와 화면 지표가 필요하면 전송과 분리한다. 기존 3배 기준과 감시 대상을 조용히 바꾸지 않는다. 운영 알림 중단은 적용 단계에서 별도 승인과 재개 방법을 확인한다.

알림 대상은 새 매수 추천, 추천의 근거 무효화, 확인된 중대한 위험, 사용자의 조치가 필요한 지속적 데이터 장애다. 추천·상태가 유지되는 동안 같은 경고를 반복하지 않는다. 기존 정기 보고 시간은 보존하고 신규 스케줄을 만들지 않는다. 외부 발송은 응답 유실 시 중복 가능성까지 고려한 발송 원장과 재시도 정책을 검증한 뒤 활성화한다.

표시 예시는 가상 자료이며 다음과 같다.

```text
오늘 매수 추천 1개
1. 가상 A사
재무 80 / 재료 70 / 위험 감점 0 / 총점 77
판정 매수 추천 다음 장 조건부
근거 재무 필수조건 통과와 공식 수주 확인
진입 조건 규칙으로 계산한 허용 범위와 유효기간 표시
무효화 조건 계약 취소 또는 검증된 가격 논리 이탈
관찰 12개 / 검증 대기 4개
```

## 저장 계약과 기존 소비자 보호

활성 소스는 `engine/`이며 `vendor/stock-assistant`와 `docs/reference`는 보관 근거로 유지한다. 기존 보고서·규칙 버전·원문·점수·등급·판정을 덮어쓰지 않는다.

새 평가는 별도 계약 버전과 규칙 버전을 사용한다. 제안 필드는 `financial_gate`, `financial_score`, `catalyst_score`, `risk_penalty`, `total_score`, `action_decision`, `entry_status`, `blocking_reasons`, `advisories`, `score_breakdown`, `coverage`, `policy_version`, `input_snapshot_ids`다. 핵심 자료 미확인에는 null과 사유를 사용한다. 기존 `decision`, `review_tier`, `score`의 의미는 보존하고 새 점수를 예전 점수인 것처럼 덮어 넣지 않는다.

필요한 저장 구조는 재무 버전과 계산 근거, 조사 대기열과 범위, 사건 및 후속 증거, 점수·행동 평가, 알림 발송 기록이다. 기존 테이블은 유지하고 추가 구조는 재실행 가능한 마이그레이션으로 만든다. 조회가 스키마를 변경하거나 새 외부 수집을 실행하지 않도록 한다. 실제 DB·로그·원문 캐시와 계좌 데이터는 Git 밖에 둔다.

현재 대시보드와 모의계좌는 기존 판정 값과 CIO 문구를 파싱하며, 명시적 CIO 1순위의 기존 등급·판정으로 신호를 만든다. 새 `매수 추천` 문구만 먼저 바꾸면 파싱 실패 또는 원하지 않은 편입이 생길 수 있다. 따라서 엔진 계약, CIO, 파서, 대시보드를 함께 검증한다. 가능하면 새 버전은 구조화된 결과를 읽고 구버전은 기존 파서를 유지한다.

새 규칙 비교 결과는 연구 전용으로 격리하고 기존 모의계좌에 공급하지 않는다. 새 정책 버전은 기존 소비자의 허용 버전에 자동 추가하지 않는다. 기존의 명시적 CIO 최종 1순위, BUY_HOLD 원문 보존, 중지 시 대기 취소와 재개 후 새 신호 요구를 유지한다. 새 매수 판정을 모의계좌 진입 조건으로 사용할지는 별도 정책 결정이며 과거 원장·거래를 재계산하지 않는다.

## 단계별 구현과 통과 조건

| 단계 | 작업과 산출물 | 다음 단계 통과 조건 |
| --- | --- | --- |
| 0 현황과 규칙 고정 | 최근 판정의 차단 사유, 자료 최신일, 조사 범위 집계와 재현 사례. 필수조건·선택 지표·배점·임계값·조사 창·진입 조건 표 작성 | 실제 추천 부족, 자료 부족, 고정 문구, 과도한 경고 차단을 구분하고 비교 규칙 고정 |

| 4 표시와 연결 | CIO·Telegram 초안·대시보드·파서의 같은 판정과 점수, 변경 알림 초안, 구버전 호환 | 원문과 구조화 값 일치, 고정 보류 문구 제거, 연구 결과의 기존 모의계좌 유입 차단 |
| 5 비교 평가 | 기존 방식, 재무만 평가, 재무·사건 통합 평가의 동일 시점 비교와 앞으로의 관측 | 데이터 가용시각 준수, 품질·비용·순위 변화 보고, 미인증 구간과 미도달 성과 분리 |
| 6 승인 후 운영 적용 | 새 계약 소비자, 백업·마이그레이션·롤백, 알림 정책 적용, 실제 예약 실행 관측 | 복구 확인, 자료 신선도, 예정 작업 성공과 승인된 Telegram 수신을 실제 확인 |

단계 0의 운영 조회는 종목·판정·차단 사유·자료일·점수·조사 상태에 한정한 읽기 전용 범위를 먼저 확인한다. 계좌·보유 상세·자격증명은 현황 집계에서 제외한다. 단계 1~4는 로컬 fixture와 승인된 공개 표본으로 개발하며 운영 DB 쓰기나 실제 Telegram 발송을 포함하지 않는다. 날짜와 소요 기간은 자료 확보 범위와 단계 0 결과를 본 뒤 산정한다.

## 검증 기준과 운영 전 확인

| 검증 사례 | 기대 결과 |
| --- | --- |
| 재무 양호, 조사 완료, 충분한 총점과 진입 조건 | 매수 추천이 실제로 생성됨 |
| 경고 한 개이지만 원인과 비결격 처리가 완료 | 경고 존재만으로 일괄 보류되지 않음 |

| 오래된 미해결 중대 위험과 높은 호재 점수 | 결격 또는 검증 보류가 총점보다 우선 |
| 뉴스 없음과 수집 실패 | 조사 완료 기준점과 null을 구분 |
| 오전·장외, 장중 가격 이탈, 시세 지연 | 다음 장 조건부·관찰·확인 불가 구분, 미래 가격 사용 없음 |
| 추천 0개·1개·5개 초과 | 기준 유지, 최대 5개만 추천, 탈락자를 추천 수 채우기에 사용하지 않음 |
| 같은 입력·재실행·새 계약·구버전 보고서 | 같은 점수·ID·판정, 중복 저장·알림 없음, 구버전 열람 정상 |
| 일·월 예산 경계·실패 예약·원장 누락 | 요청 전 차단과 기존 안전 제한 보존 |
| 새 정책의 1순위와 기존 모의계좌 | 정책 전환 승인 전에는 기존 원장에 유입되지 않음 |

추천률을 높이는 것 자체를 성공 기준으로 삼지 않는다. 정상 사례의 매수 추천 가능성, 잘못된 제외·승격, 장기 검증 대기 비율과 원인, 사건 중복·누락, 자료 최신성, 평가 근거의 설명 가능성, API 비용을 먼저 비교한다. 실제 과거 자료의 공시·관측·가용시각이 재현되는 구간에서만 성과 비교를 하고, 미재현 구간은 앞으로의 관측으로 검증한다.

가중치 선정에 사용한 사례와 이후 평가 사례를 분리한다. 기존 추천 성과, 새 규칙의 사건별 사후 수익률, 모의계좌 손익은 서로 다른 결과로 보고한다. 가격 정지·상폐·기업행위·수수료와 미도달 5·20·60거래일 성과를 구분한다. 추천 후 수익률이 개선되었다는 주장은 별도의 충분한 관측 근거가 있을 때만 한다.

변경 후 저장소 전체 검증 명령을 실행한다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/verify.ps1 -Python <Python 3.12 이상 실행 파일>
```

운영 적용 전에 배점·임계값·진입 조건과 비교 결과를 확정하고 새 계약 소비자와 모의계좌 경계를 확인한다. 승인된 운영 단계에서 DB와 배포 백업·복구, 환경·안전 한도 보존, 새 보고서 생성, 실제 예정 실행과 Telegram 수신을 각각 검증한다. 컨테이너 health와 로컬 테스트만으로 다음 예약 실행이나 Telegram 수신 성공을 대신하지 않는다.

## 근거와 우선 착수 작업

기존 정책은 [승인 요구사항](../specs/2026-09-21-hermes-stock-investment-assistant.md), [뉴스 발견 결정](../../decisions/0003-news-discovery.md), [아키텍처](../../../ARCHITECTURE.md)를 따른다. 모의계좌 경계는 [운용 규칙](../../../../docs/rules-and-validation.md)과 [Hermes 모의계좌 연결](../../../../docs/hermes-paper-account.md)에 연결한다. [데이터 확보 조사](../../../../docs/data-coverage.md)의 수량과 관측은 2026-09-30 당시 기록이므로 현재 확보 범위로 사용하지 않는다.

공식 자료 확인일은 2026-10-12 KST다. [OpenDART 공시검색](https://opendart.fss.or.kr/guide/detail.do?apiGrpCd=DS001&apiId=2019001)은 기간·정정 보고서를 포함한 조회와 접수번호를 제공한다. [단일회사 전체 재무제표](https://opendart.fss.or.kr/guide/detail.do?apiGrpCd=DS003&apiId=2019020)는 보고서 코드와 연결·별도 기준을 구분한다. [NAVER API HUB 뉴스검색](https://api.ncloud-docs.com/docs/naver-api-hub-search-news)은 제목·요약·원문 URL과 공급자 기사시각을 제공하고 표시 건수·검색 시작 위치에 제한이 있다. 이 제공 범위만으로 과거 전체 뉴스나 위험 조사가 완전하다고 주장하지 않는다.

첫 구현 단위는 **재무 통과 목록과 항목별 점수 분리, 실제 보류 사유 집계, 검증 미완료의 작업 상태 관리**다. 그 다음 기업별 사건 기록을 연결하고 총점과 매수 판정을 추가한다. 고정 문구만 바꾸거나 점수 기준을 낮추는 작업으로 먼저 적용하지 않는다.

## 진단과 재무 평가 기반 구현

2026-10-12 로컬 구현에는 기존 보고서의 읽기 전용 진단, 가격 이력 없이 전체 저장 종목을 검사하는 재무 평가, 보완·분류·뉴스 검토 대기 목록, 별도 연구 DB의 평가 이력과 확인 작업 상태가 있다. [실행 방법과 초기 점수 규칙](../../runbooks/financial-research.md)을 따른다. 기존 후보 생성·판정·모의계좌 정책은 유지한다.

이 단계의 재무 점수는 기본 흑자·OCF, 검증된 3개년 이력, 기존 회전율 추세와 FCF를 사용하는 비교용 기반이다. 이익 변동성·현금흐름의 질·업종별 구간을 충분히 검증한 최종 재무 모델로 표현하지 않는다.

## 확대 수집과 통합 판정 연결

2026-10-12 다음 구현에서는 별도 연구 입력 DB에 DART 전체 일반주 회전 수집, 3개년·TTM의 연결/별도 일치, 접수번호 캐시·정정 갱신, 재무 통과 기업의 예산 제한 뉴스 조회를 연결했다. 검토한 사건과 검색 범위의 근거 ID를 입력하면 뉴스 N·위험 R·총점 S와 `BUY_RECOMMENDATION/WATCH/VERIFY_PENDING/EXCLUDED` 판정까지 한 새 계약으로 계산한다. 최대 5개의 한 목록과 조건부 매수 추천 렌더러·검토 대기 목록을 제공한다.

원문 검토는 공식 근거·검토자·판단 근거를 요구한다. 현재 뉴스 검색의 최신 페이지를 3년 아카이브 확보로 표시하지 않는다. 자세한 명령·지원 범위·검토 계약은 [실행 방법](../../runbooks/financial-research.md)에 기록했다.

## 승인된 자동 수집·운영 연결

사용자가 과거 뉴스 자동 수집, 실제 데이터 검증, 운영 서버와 Telegram 적용을 명시적으로 승인했다. 추가 뉴스 아카이브는 없다고 확인했다. 2026-10-12 구현은 Naver 날짜순 페이지의 재개·겹침 확인·1,000 위치 한도 상태, 5개 주요 위험 검색 보완, DART 구조화 계약 원문의 사건 연결, 공유 인증 캘린더와 통합 운영 주기를 포함한다. 좁은 위험 검색을 전체 뉴스 검토 완료로 사용하지 않는다. 불완전한 자료는 null·확인 대기로 유지한다.

새 운영 조회 API와 CIO 문구를 연결하고 아침·저녁·주간 cron에서 스크립트 출력의 점수·판정을 직접 Telegram에 전달한다. 기존 일정·수신처·API 예산·공유 인증과 실제 주문 비활성을 보존한다. 장중 거래량 cron만 끈다. 당일 마감이 공식 캘린더로 확인된 경우 KRX 당일 일봉을 확보하는 opt-in 경로를 추가하며 기존 일봉 명령의 기본 동작을 유지한다. 대시보드와 기존 모의계좌는 구버전 계약을 유지하고 새 순위를 자동 소비하지 않는다.

실제 검증에서 재무 표본 7개·Naver 첫 5페이지·공식 계약 원문 5개가 연결되었다. 첫 운영 수동 실행은 25개 기업 중 재무 묶음 17개를 확보했고 보고서와 Telegram `delivered` 기록을 확인했다. 과거 뉴스가 부분 확보 상태여서 실제 매수 추천은 0개다. 로컬 경계·회귀 검증과 실제 관측 수량은 [운영 실행 기록](../../runbooks/financial-research.md)에 구분해서 남긴다. 전체 3년 뉴스·다음 예정 실행·미도달 수익률 검증은 완료로 표현하지 않는다.

2026-10-13 후속 관측에서는 아침 예약 실행·전달 성공과 전날 저녁의 KRX 최신 일봉 미공개 실패를 구분했다. 새 정책 `unified-research-2026-10-13.1`은 최신 일봉 미공개만 연구 주기의 가격 확인 대기로 다루며, 재무·뉴스 수집은 계속하고 매수 추천은 차단한다. 과거 공백·인증·전송 오류는 기존 실패 처리를 유지한다. 미완료 뉴스 우선 재개, 이동한 기준 행 탐색, 위험 검색의 개별 한도 처리, 뉴스 조사 기업의 배치 안 공시 갱신과 한국어 진척 표시를 보완했다. 엔진 319개·대시보드 및 배포 회귀 93개 검증을 통과했고, 운영 재무 확보 기업 78개·수동 저녁 경로의 실제 Telegram 전달을 확인했다. 오늘 20:00 실제 예정 실행과 3년 뉴스 조사 완료는 아직 미관측이다.
